UCIe Link Training (LTSM) Field Guide

The Link Training State Machine takes a UCIe link from power-on to ACTIVE: bring up the sideband, check and repair clock, valid and data lanes at 4 GT/s, switch to the target speed, calibrate and center, verify, and hand over to the Adapter. It also runs retrains, power states and error recovery. This guide walks every state in order, explains why each step exists, and shows the sideband handshakes that drive it.

1 · Why link training exists

Four problems the LTSM solves. Every state maps to at least one of them.

Two independent dies

Agree on everything, step by step

The dies come out of reset at different times, from different vendors, maybe at different maximum speeds. Every sub-state ends with a request/response pair on sideband, so neither die moves on until the other is ready.

Spec§4.5.3.4 intro, p.155 · §4.5.3, p.131

Manufacturing defects

Find and route around bad bumps

Micro-bumps open or short. Training checks clock, track, valid and every data lane with known patterns, then repairs (Advanced Package, using redundant lanes) or narrows the link (Standard Package).

Spec§4.5.3.3.3–4.5.3.3.6, p.146–155 · §4.5.3.4.13, p.167

Signal integrity at speed

Set Vref, center the clock, deskew

Margins shrink as speed rises. The LTSM first gets a working link at 4 GT/s, then moves to the target speed and calibrates: Tx self-cal, Rx clock cal, valid and data centering, Vref, per-lane deskew, then a final link check.

Spec§4.5.3.4, p.155–167

Change over time

Retrain, recalibrate, degrade

Temperature and voltage drift. PHYRETRAIN re-runs training on errors or request, LINKSPEED can degrade speed or width, and Runtime Recalibration uses the Track lane to adjust while data keeps flowing.

Spec§4.5.3.7, p.168 · §4.6, p.173

3 · Training triggers and RESET

What starts mainband training

  • Software writes 1 to Start UCIe Link Training in the UCIe Link Control register.
  • The Adapter makes a NOP → Active transition on RDI while status is Reset.
  • The SBINIT pattern (two iterations of 64-UI clock pattern + 32-UI low) is seen on any sideband receiver pair (when management transport is not up).
  • With management transport up: {SBINIT done req} from the partner, or software Retrain Link in a Management Port structure.

Hardware may retry training an implementation-specific number of times, then waits in RESET for a new trigger. If software- or RDI-triggered training fails, or the link drops from up to down on a PHY timeout, the PHY must raise a fatal error to the Adapter on RDI.

Spec§4.5, p.124–125

RESET: at least 4 ms, every time

  • Minimum 4 ms on every entry, for PLLs and other initialization.
  • Exit needs stable supplies, an 800 MHz sideband clock, stable PHY and Adapter clocks, mainband clock at the slowest rate (2 GHz for 4 GT/s), SoC not holding reset, and a training trigger.
  • All mainband transmitters tri-stated; receivers may be off; sideband receivers enabled.
  • Without management transport up, sideband register accesses arriving in RESET may be completed as Unsupported Requests, with credits returned.

Spec§4.5.3.1, p.132–133

4 · SBINIT: bring up the control channel

Everything after this point is coordinated over the sideband, so it comes first. It runs at 800 MT/s with the 800 MHz sideband clock.

1

Send repeating 64-UI clock pattern (1010…) + 32-UI low on sideband data, with the sideband clock strobing during the 64 UI. Advanced Package drives both TXDATASB and TXDATASBRD, and both clocks.

2

The partner samples every data/clock combination (4 on Advanced). Detection = 128 UI of clock pattern seen.

3

On detection, send four more iterations, then stop and enable the sideband for messages. If nothing is detected, alternate 1 ms sending / 1 ms quiet; at 8 ms, TRAINERROR.

4

Send {SBINIT Out of Reset} until the same message is received (8 ms timeout). On Advanced it carries the chosen data/clock assignment; both sides then use that "functional sideband".

5

{SBINIT done req} / resp. When sent and received, go to MBINIT.

7 · The test primitives everything is built from

MBINIT and MBTRAIN reuse four operations. They differ in who drives the sweep and who logs results.

Tx-initiated point test (§4.5.1.1)
  1. {Start Tx Init D to C point test req} with pattern, mode and compare setup; partner arms comparators, responds.
  2. {LFSR clear error req/resp}: both reset LFSRs and results.
  3. Tx sends the pattern for the set number of cycles; Rx compares every UI.
  4. {Tx Init D to C results req/resp}: Tx reads the partner's log.
  5. {End Tx Init D to C point test req/resp}.

Spec§4.5.1.1, p.125–126

Eye width sweep and Rx-initiated variants

An eye width sweep repeats the point test across PI (clock phase) settings to find the passing range. Rx-initiated versions let the receiver drive the test and keep its own results, then share them, used where the receiver is optimizing (Vref, deskew).

Spec§4.5.1.2–4.5.1.4, p.127–130

Patterns
  • LFSR: G(X) = X23+X21+X16+X8+X5+X2+1 (same as PCIe), lane-dependent seed (lane mod 8).
  • VALTRAIN: four 1s, four 0s.
  • Per Lane ID: 16-bit pattern carrying the lane number; never scrambled.
  • Burst mode (burst/idle/iteration counts) or continuous mode.

Spec§4.4.1, p.120 · Table 4-5, p.126 · Table 4-7, p.151

Two comparison modes

Per-lane: a sticky error bit per lane once errors exceed the threshold; used to find which lanes to repair (N = 68 for x64 Advanced, 34 for x32, 16 or 8 for Standard). Aggregate: any-lane errors per UI counted in a 16-bit counter; used for module-level margining.

Spec§4.4, p.119–120

8 · PHYRETRAIN, TRAINERROR and PM

Retrain: four ways in, one negotiation

  • Adapter-directed: RDI request Retrain → stall handshake → {LinkMgmt.RDI.Req.Retrain}.
  • PHY-initiated: Valid framing error → pl_error with the bad data → stall → Req.Retrain.
  • Remote request: partner's Req.Retrain → stall → Rsp.Retrain.
  • From LINKSPEED: Runtime Link Test Control changed.

Then both send {PHYRETRAIN.retrain start req} with a retrain encoding; mismatches resolve to the more severe one (try it on the right). All modules of a link must resolve the same way.

TRAINERROR

Transmitters tri-stated. If sideband works, enter via {TRAINERROR Entry req/resp} (8 ms timeout). Exit to RESET is implementation-specific: quickly if RDI is not in LinkError, but held as long as RDI is in LinkError. In-flight sideband packets finish first.

Spec§4.5.3.8, p.171–172

L1 and L2

Entered when RDI reaches PM. Transmitters tri-stated. L1 exit → MBTRAIN.SPEEDIDLE (restores the last ACTIVE speed). L2 exit → RESET and full training. Exits are coordinated with RDI's PM exit flow.

Spec§4.5.3.9, p.172 · §4.5.3.4.3, p.158

L2 Sideband Power Down

Optional, negotiated via Sideband Feature Extensions; all modules must agree. Most sideband logic may power off in L2. Wake: sideband clock = 1, data = 0 for ≥ 100 ns on both sides, then RESET, SBINIT and full training.

9 · Runtime Recalibration

1

Receiver enables its Track buffers and sends {RECAL.track pattern init req}.

2

Partner responds and starts the Track pattern with the forwarded clock (re-enabling a gated clock if needed).

3

Receiver recalibrates and sends {RECAL.track pattern done req}, or, if TARR was negotiated and it wants help, sends {RECAL.track tx adjust req} with a delay correction in 1/64 UI steps.

4

Partner may adjust its Tx and answers; it must avoid the 8 ms timeout (Stall every 4 ms recommended).

Data keeps flowing: mainband data with correct valid framing must still be sampled and processed during recalibration. TARR (Tx Adjustment during Runtime Recalibration) lets the transmitter absorb drift, so receivers need less margin and less power. On unterminated links the idle Track alternates low and high across iterations to limit aging.

Spec§4.6, p.173–175 · §4.5.3.3.1 (TARR), p.138
