UCIe RDI Field Guide

The Raw Die-to-Die Interface is the contract between the Die-to-Die Adapter and the Physical Layer. It is the lower sibling of FDI: same naming, same handshakes, same state encodings, but one level down, where the far side of every state change is the remote PHY instead of the remote Adapter. This guide covers what RDI is for, how it ties into link training, every signal, the state rules and the reason behind each one, cycle-level scenarios, and how to verify it.

1 · Why RDI exists

Every RDI rule serves one of four goals. When you know which one a rule serves, it is easy to remember.

Separation

Any Adapter on any PHY

The Adapter handles flits, CRC and retry. The PHY handles lanes, training, repair and the analog front end. RDI is the fixed boundary between them, so an Adapter from one team or vendor can sit on a PHY from another. The spec names a common interface as the way to keep Bus Functional Models consistent and to make interop testing tractable.

Spec§1.1.4 Interfaces, p.44 · §10.1, p.521

Abstraction

One interface, one to four modules

A single RDI instance can front one module or a group of modules that form one logical link. The Multi-module PHY Logic (MMPL) hides the module count: the Adapter sees one byte stream, one state machine and one pl_lnk_cfg width. Byte order on RDI does not change with module count; reshuffling bytes across modules is the MMPL's job.

Spec§10.1, Figure 10-1, p.521–522 · §3.5, p.89 · §10.3.1, p.561

Latency

Raw bytes, no extra handshakes in the data path

RDI carries bytes, not protocol meaning: no stream IDs, no DLLP channel, no cancel. The receive path has no backpressure, so the PHY never waits on the Adapter. lp_irdy can rise a few cycles before data as an early wake hint, so a gated PHY transmit path is ready when the flit arrives.

Spec§10.1.4, p.532–533 · §10.1.2, p.529

Power

The PHY can sleep without losing events

Two four-phase handshakes, lp_wake_req/pl_wake_ack and pl_clk_req/lp_clk_ack, let each side gate clocks in Reset, LinkReset, Disabled and PM. In L1 or L2 the PHY can turn off its mainband PLL; the sideband logic and its PLL stay on in L1 so the link can be woken.

Spec§10.1.3, p.530–531 · §10.1.7, p.535

One-line mental model. FDI asks the Adapter to agree a state with the remote Adapter using {LinkMgmt.Adapter*} messages. RDI asks the PHY to agree a state with the remote PHY using {LinkMgmt.RDI.*} messages. Same request/status wires, same table of allowed transitions, one layer lower.

Spec§3.5, p.89 · §10.2 note, p.539 (RDI signal list is a proper subset of FDI's) · Table 7-8, p.275–276

2 · Where it sits

One RDI per Adapter. Above it, one FDI per protocol stack. Below it, the PHY: logical layer, multi-module logic, and the analog front end of each module.

Ordering rules between them
  • Up: RDI Active before an Adapter LSM may negotiate Active; Adapter LSM Active before vLSMs.
  • Retrain: RDI goes first, then Retrain is pushed to every Adapter LSM that is Active.
  • PM: bottom-up in reverse. vLSMs, then each Adapter LSM, and only when all are in PM does RDI go to PM.
  • LinkError: RDI first, then all Adapter LSMs, then vLSMs.
  • LinkReset / Disabled: reach RDI only if every Adapter LSM is there. Priority LinkError › Disabled › LinkReset.

3 · Link training and RDI: what each shows

The PHY has its own Link Training State Machine (LTSM). RDI shows a simpler view of it to the Adapter. The end of Stage 2 is the exact moment RDI moves from Reset to Active.

Stage 0Die reset, independent on each die. RDI held in reset, all outputs 0.
Stage 1Sideband initialization (SBINIT). RDI status Reset.
Stage 2Mainband init and training (MBINIT, MBTRAIN), then LINKINIT: RDI Reset → Active.
Stage 3Adapter parameter exchange on sideband, then FDI Reset → Active.

5 · State machine and the request/status contract

The Adapter asks on lp_state_req. The PHY answers on pl_state_sts only after the matching sideband handshake with the remote PHY. The PHY may also change status on its own: a framing error, a remote request, a fatal error.

Reading the table on RDI

  • ¹ edge: request must be NOP for at least one clock while status is Reset, then change. An Adapter that drives Active straight out of reset is ignored. §10.3.3.1, p.565
  • ² From Active.PMNAK an Active request moves status back to Active. Table 10-4 note b, p.565
  • Unlike FDI in Flit mode, the Adapter may request Retrain on RDI: software Retrain bit, CRC or parity error count over a threshold, a Raw Format Protocol Layer request, or another implementation reason. §10.3.3.4, p.566
  • On RDI, the remote PHY can also force Reset→LinkError and Active→LinkError with a sideband request. §10.3.3.1 rule 4, p.565 · §10.3.3.7, p.568
  • Retrain → LinkReset/Disabled may pass through Active first ("transitional state"). §10.3.3.4 rule 2, p.567
  • After LinkError, LinkReset or Disabled → Reset, the PHY must not start training until it sees NOP→Active or a Chapter 4 training trigger. §10.3.3.8, p.569

6 · The handshakes

Three four-phase handshakes on the wires: request rises, acknowledge rises, request falls, acknowledge falls. Each needs at least one cycle between request and acknowledge, so there is never a combinational loop. RDI has no rx_active handshake; the PHY's receiver is ready by the time LTSM reaches LINKINIT.

The Active Entry handshake (sideband, PHY to PHY)

Required on every entry to Active, from Reset, Retrain or L1. Active.PMNAK → Active does not count; it is a sub-state.

1

PHY finishes training, does the pl_clk_req handshake and raises pl_inband_pres.

2

Adapter sees pl_inband_pres = 1, does the lp_wake_req handshake, and drives lp_state_req NOP → Active.

3

Only after sampling lp_state_req = Active does the PHY send {LinkMgmt.RDI.Req.Active}. Either side may start first.

4

Each PHY answers the remote request with {LinkMgmt.RDI.Rsp.Active}, but only once it has also sampled Active on its own RDI.

5

When a PHY has both sent and received Rsp.Active, it moves pl_state_sts to Active. Stage 3 (Adapter parameter exchange) can begin.
