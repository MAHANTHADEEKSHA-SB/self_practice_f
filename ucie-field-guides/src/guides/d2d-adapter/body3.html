Retry buffer ceiling. MAX_UNACKNOWLEDGED_FLITS is at most 127, so a buffer bigger than 127 flits buys nothing: 127 × 256B = 32,512 bytes for 256B formats, 127 × 68B = 8,636 bytes for 68B. Real designs size for the Ack round trip instead (next card).

Sizing for the round trip. Buffer flits ≥ (Ack round-trip time ÷ Flit Time) + margin. With a 40 ns round trip at 2 ns per flit that is about 20 flits, 5 KB. Alternating Ack flits keep the round trip short, which is the reason for the rule.

13 · Verification

An Adapter testbench needs an FDI agent per stack (Protocol Layer side), an RDI agent (PHY side), a sideband message model, and a reference model for flit packing, CRC and Retry. Use crc_gen.vs as the CRC reference.

Checkers

  • Parameter exchange order: DP AdvCap → UP AdvCap → DP FinCap (→ CXL round); UP never sends FinCap. §3.2.1.2, p.65
  • Negotiated format matches Truth Table 1 or 2 for the bits exchanged. Tables 3-9, 3-10, p.88
  • No 68B Flit Mode advertised when pl_max_speedmode = 1. Table 3-1, p.63
  • Every transmitted flit's CRC matches the reference over the final bytes. §3.7, p.92
  • Header: alternation of explicit S and Ack/Nak; S ≠ 0 on payload; Nak S = N−1. §3.8, p.93 · Table 3-5
  • Unacknowledged flits ≤ min(buffer, 127). §3.8, p.94
  • Multi_Protocol_Enable: no two consecutive same-stack flits, including replay. §3.1, p.59
  • NOP flits: Protocol ID 00b, zero body, never forwarded on FDI. §3.1, p.59
  • 68B: transfers in 256B multiples; PDS padding rules; replay starts 256B-aligned. §3.3.2.1, p.73
  • Adapter LSM PM request only with empty retry buffer and (CXL) both vLSMs in PM. §3.6, p.90–91
  • Parity: 64N bytes after each 256·256·N data bytes; correct bit 0. §3.9, p.95

Scenarios that find real bugs

  • CRC error on CRC1 of a Latency-Optimized flit after half 0 was consumed. §3.3.4 · §10.2.5
  • Corrupt the last Ack before idle; check replay at 375 Flit Times. §3.8, p.93–94
  • PDS header with 1, 2 and 3 bit errors, Retry on and off. §3.3.2.1, p.73–74
  • Retimer partner stalling every 4 ms for 50 ms; then stalling every 9 ms. §3.2.1.2, p.70
  • Nak during replay; Nak for the first replayed flit; Nak with sequence wrap 255→1. §3.8
  • Stack 0 LinkReset while stack 1 streams; then PM on stack 1 only (virtual L2 on stack 0). §3.5 · §10.3.3.8
  • Speed degrade at runtime: Retry stays on, format unchanged. §3.4 · §3.8
  • Parity enabled on one direction only; parity Nak; parity across L1 exit. §3.9

Coverage

  • Every row of Truth Tables 1 and 2, plus "no valid format".
  • Each flit type × Ack/Nak encoding × Protocol ID × stack ID.
  • 68B stream lengths 1…4 flits before PDS (each padding case).
  • Retry: error in each 64B chunk of a flit, in header vs payload vs CRC bytes.
  • Stack mux: each arbitration pattern, both bandwidth-limit settings.

14 · Test yourself

Interview-style questions, basic to advanced.

Name the four jobs of the D2D Adapter. Basic

Reliable data transfer (CRC and Retry, or parity), arbitration and multiplexing of protocol stacks, link state management, and protocol/parameter negotiation with the remote partner.

Spec§3.0, p.58

In Format 2, what does the Adapter add to the Protocol Layer's 64 bytes? Basic

A 2-byte Flit Header in front and a 2-byte CRC behind, computed over the header and payload (66 bytes, zero-extended to 128). Then it shifts the result across the RDI bus, since each flit is 4 bytes longer than 64.

Spec§3.3.2, p.71 · §3.3.2.1, p.73

Which format is mandatory for PCIe Flit Mode, and which for CXL 256B Flit Mode? Basic

PCIe Flit Mode: Format 3, Standard 256B End Header. CXL 256B Flit Mode: Format 4, Standard 256B Start Header. Format 6 is strongly recommended for both (for PCIe, if the capability is supported).

SpecTable 3-7, p.85

Who sends {FinCap.Adapter}, and why not both sides? Intermediate

Only the Downstream Port, after the Upstream Port has replied to its advertisement. One decider means both dies always end up with the same configuration. For Streaming there is no FinCap at all; each side ANDs what it sent and received.

Spec§3.2.1.2, p.65–67

Why does UCIe alternate explicit-sequence flits with Ack/Nak flits? Intermediate

To return Acks faster, which shortens how long flits stay in the retry buffer and lets it be smaller. Consecutive explicit-sequence flits are allowed only when no Ack/Nak is pending.

Spec§3.8, p.93

Why does REPLAY_TIMEOUT_FLIT_COUNT also count idle Flit Times? Intermediate

Because UCIe lets a transmitter stop sending NOP flits when idle, to save power. A count of transmitted flits would freeze, and an unacknowledged flit would never be replayed. Counting idle Flit Times keeps the counter tied to time; replay is scheduled at ≥ 375.

Spec§3.8, p.93

What is a PDS and when must the Adapter send one? Intermediate

Pause of Data Stream, in 68B format: a special 2-byte header followed by zeros to the next 64B boundary, two more zero 64B chunks, and zeros up to a 256B multiple. Sent before pausing an idle stream (unless sending continuous NOPs instead), before replaying, and before acking a stall for Retrain.

Spec§3.3.2.1, p.73

With Multi_Protocol_Enable, only stack 0 has traffic. What does the link carry? Advanced

Stack-0 flits separated by NOP flits (or stack-1 flits when there are any): never two stack-0 flits in a row. NOPs bypass the retry buffer and are dropped by the receiving Adapter. The same applies during replay.

Spec§3.1, p.59

Why is there no {LinkMgmt.Adapter0.Req.Retrain}? Advanced

Retrain (and LinkError) concern the shared physical link, so they start at RDI and are pushed up to every Active Adapter LSM. The Adapter asks for a retrain by requesting Retrain on RDI. LinkReset and Disabled, by contrast, are per stack and are negotiated per Adapter LSM.

Spec§3.5, p.89–90 · Table 7-8 · §10.3.3.4

Why does runtime parity use a stride of 64·N bytes? Advanced

Every byte covered by one parity bit travels on the same lane, because byte k of each 64B transfer always goes to lane k on a x64 module. So parity errors point to a specific lane. (This is a consequence of §3.9 and §4.1.1, not stated as a reason in the spec.)

Derived§3.9, p.95 · §4.1.1, p.98

A Latency-Optimized flit passes CRC0 and fails CRC1. What happens? Advanced

Half 0 may already have been forwarded and consumed. Half 1 is cancelled on FDI and a Nak triggers replay of the whole flit. When the replay arrives, the receiver must not consume half 0 a second time; the FDI cancel rules cover this.

Spec§3.3.4, p.81 · §10.2.5, p.551

The link degrades from 32 GT/s to 12 GT/s at runtime. Can Retry be turned off? Can the format change? Advanced

No to both. Retry stays enabled until the next link initialization (RDI to Reset), and protocol and flit format are fixed until the PHY goes to Reset.

Spec§3.8, p.93 · §3.4, p.85
