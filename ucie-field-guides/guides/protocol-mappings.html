UCIe Protocol Mappings Field Guide

UCIe carries PCIe, CXL, Streaming (any vendor protocol) and Management Transport. Each protocol has a few allowed flit formats, and each mapping removes the parts of the native protocol that UCIe already handles (CRC, retry, link training, PM DLLPs). This guide shows which formats each protocol uses, what the Protocol Layer must change, and why.

1 · Why protocol mappings exist

Reuse

Keep the PCIe/CXL transaction layers

Existing PCIe and CXL controllers, software and compliance carry over. UCIe only changes the layers below the transaction layer: framing, reliability and link management.

Spec§2.0, p.51 · §11.1, p.580

Remove duplicates

Don't do reliability twice

The Adapter already does CRC and retry, and the PHY trains the link and manages power. So the native protocol's LCRC, Ack/Nak, PM and link-management DLLPs, and 8b/10b or 128b/130b encoding are not used.

Spec§2.1.2–2.1.3, p.53 · §2.3.2, p.55 · §10.3.1, p.561

Interop vs latency

Standard formats and faster ones

Standard 256B flits match the PCIe/CXL formats exactly, so any vendor interoperates. Latency-Optimized flits let the receiver use each 128B half early, for lower latency between parts that support them.

Spec§2.1.2, p.53 · §2.2.2, p.54

Openness

Streaming for anything else

Any protocol can ride UCIe as "Streaming", in Raw Format or (optionally) in the Adapter's flit formats with CRC and retry. Management Transport uses the same paths for management packets.

Spec§2.4, p.56 · §2.5, p.57

4 · CXL 256B Flit Mode

  • Raw (optional): Retimer use; the Protocol Layer does CRC, retry, FEC and viral/poison containment.
  • Latency-Optimized (strongly recommended): Format 5 or 6. The Protocol Layer can consume the flit at each 128B boundary. Format 6 gives CXL.io 4 more TLP bytes, and CXL.cachemem an extra 14-byte H-slot ordered between slots 7 and 8.
  • Standard 256B Start Header (Format 4): mandatory, for interop with vendors that only support baseline CXL formats.
  • For CXL.io in any 256B mode, Ack, Nak, PM and Link Management DLLPs are not used; Flit_Marker rules as in CXL.

Spec§2.2–2.2.3, p.54–55

Viral containment at low latency

lp_corrupt_crc

For CXL.cachemem with Adapter retry, the Protocol Layer can ask the Adapter to corrupt the CRC of an outgoing flit (recommended: XOR with syndrome 138Eh, chosen so no 1- or 2-bit error aliases to it). The receiver sees a CRC error and Naks; the Adapter has already overwritten that flit in its retry buffer with the next flit, which carries the viral information. So bad data is never accepted, and the replay delivers the viral notification.

SpecTable 10-3 (lp_corrupt_crc), p.540 · §2.2.2, p.54

5 · CXL 68B Flit Mode

  • Not supported when the negotiated maximum rate is above 32 GT/s.
  • Raw (optional, Retimers): Protocol Layer does CRC and retry.
  • 68B Flit Format (mandatory at ≤ 32 GT/s): the Protocol Layer presents 64B (no Protocol ID, no CRC) on FDI; the Adapter adds the 2B header and 2B CRC and shifts.

Spec§2.3–2.3.2, p.55

What changes inside the flit

  • CXL.io: no Ack, Nak or PM DLLPs; no Protocol Layer retry; LCRC driven 0 and ignored; STP sequence number and CRCs recommended 0.
  • CXL.cachemem: the "Ak" field is reserved and Retry flits are not used. Link initialization begins by sending INIT.Param without waiting.
  • Viral containment must be handled inside the Protocol Layer. Because Retry flits (which carry viral in CXL 68B) are unused, the spec recommends relying on CXL error isolation at the Root Port for fatal errors.

Spec§2.3.2, p.55–56

6 · Streaming, Management Transport and Raw

Streaming

The default protocol if neither PCIe nor CXL is advertised. Raw Format is mandatory in the Adapter; Protocol Layer interop is vendor-defined. With the Streaming Flit Format capability, the 68B (≤ 32 GT/s), Standard 256B and Latency-Optimized formats may be used, giving CRC and retry. The Protocol Layer fills only Protocol ID bits [7:6] and must never use 00b (that marks Adapter NOPs).

Spec§2.4–2.4.4, p.56–57 · §3.3.3, p.76

Management Transport

Carries management network packets (MTPs) over the mainband. Raw or any 256B format; 68B is not allowed. The Management Port Gateway ignores Adapter bytes on receive. Can be multiplexed on the same stack as CXL.io, PCIe or Streaming.

Spec§2.5, p.57 · §3.3.3–3.3.4 Management Flit notes

Raw Format for Retimers

For every protocol, Raw Format exists mainly for UCIe Retimers bridging to an off-package interconnect. The protocol's own CRC, retry and FEC protect the end-to-end path, and Retimers are encouraged to count errors to characterize the off-package link, which dominates the error rate.

Spec§2.1.1, p.53 · §2.2.1, p.54 · §2.3.1, p.55

7 · Why each rule exists, with real-time examples

PCIe§2.1.2–2.1.3 p.53

No Ack/Nak, PM or Link Management DLLPs

Over UCIe, PCIe does not use Ack/Nak DLLPs (Non-Flit), nor PM and Link Management DLLPs (any mode). Other DLLPs, such as flow-control updates, are still used.

Why

Reliability is the Adapter's CRC and retry; power states are the FDI/RDI handshakes plus sideband messages; link state is the LTSM. Native DLLPs for those would duplicate mechanisms and could disagree with them.

Real-time example

A PCIe controller's L1 entry is driven by its idle timer and an FDI L1 request; no PM_Enter_L1 DLLP is sent. Credits still flow as UpdateFC DLLPs, which the Adapter packs into DLP bytes.

If you break it

A controller that waits for a PM_Request_Ack DLLP before entering L1 never gets one.

Check it in the spec
  • SpecDLLP rules §2.1.2, p.53 · §3.6, p.91
PCIe§2.1.3 p.53 · §2.3.2 p.55

Keep the 68B framing, zero the reliability fields

In 68B mode the Protocol Layer still produces CXL.io-style framing tokens and LCRC fields, but drives LCRC as 0 (receiver ignores it) and is recommended to drive STP sequence number, DLLP CRC, frame CRC and parity to 0.

Why

Keeping the framing format lets existing parsers work unchanged, so the controller design stays close to a standard CXL.io one. Zeroing the protection fields avoids computing work that the Adapter's CRC already covers.

Real-time example

A TLP in a 68B flit still starts with an STP token, but its sequence number field is 0 and its LCRC is four zero bytes.

If you break it

A receiver that checks LCRC flags every TLP as corrupted.

Check it in the spec
  • SpecLCRC and STP rules §2.1.3, p.53 · §2.3.2, p.55
PCIe§2.1.2 p.53 · §2.1.3 p.53

Framing errors are internal errors

If the Protocol Layer detects a framing error, it is permitted to treat it as an uncorrectable internal error.

Why

Flits reaching the Protocol Layer were already CRC-checked and, with retry, replayed if bad. A framing error therefore almost certainly comes from a logic or buffer fault inside the chip, not from the wire.

Real-time example

An SRAM soft error in a receive buffer corrupts an STP token. The Protocol Layer reports an uncorrectable internal error instead of triggering native PCIe recovery.

If you break it

Triggering PCIe-style link recovery cannot help: the link itself is fine.

Check it in the spec
  • SpecPermission to treat as UIE §2.1.3, p.53
  • IllustrativeThe SRAM example
CXL§2.2.2 p.54

Format 6 adds payload, not just latency

Format 6 gives CXL.io 4 more bytes of TLP per flit, and CXL.cachemem a 14-byte H-slot between slots 7 and 8.

Why

Splitting the flit into CRC-protected halves costs some bytes. Format 6 hands unused Adapter bytes back to the protocol, recovering packing efficiency so the latency gain does not cost bandwidth.

Real-time example

Every Format 6 cachemem flit carries one more 14-byte H-slot than a Format 5 flit, at the same link rate and the same latency.

If you break it

A Protocol Layer that packs Format 6 rules while Format 5 was negotiated writes into bytes the Adapter treats as reserved; the remote Protocol Layer ignores them and loses the slot.

Check it in the spec
  • SpecExtra bytes and slot position §2.2.2, p.54
  • IllustrativeSlot count and percentage
CXLTable 10-3 p.540

Corrupt the CRC to contain viral

With Adapter retry, the CXL.cachemem Protocol Layer asserts lp_corrupt_crc with the last chunk of a flit (or 128B half) that must not be consumed. The Adapter corrupts its CRC and overwrites it in the retry buffer with the next flit, which carries viral.

Why

The Protocol Layer may discover a problem after it has already started sending a flit. Corrupting the CRC guarantees the receiver discards it, and the replay naturally delivers the viral flit in its place, with no extra latency on the normal path.

Real-time example

See the "Viral with lp_corrupt_crc" scenario below.

If you break it

Not overwriting the retry-buffer entry: the replay resends the poisoned flit with a good CRC, and the receiver accepts it.

Check it in the spec
  • SpecRules for Standard and Latency-Optimized flits; 138Eh Table 10-3, p.540
CXL§2.3.2 p.55–56

68B CXL: viral stays in the Protocol Layer

In 68B mode, CXL Retry flits are not used, so viral containment must be handled within the Protocol Layer; the spec recommends CXL error isolation at the Root Port for fatal errors.

Why

Native CXL 68B carries viral in Retry flits, which UCIe removes. Error isolation resets only the virtual hierarchy below a Root Port instead of the whole host, so it is a better fit than viral when the usual viral transport is missing.

Real-time example

A Type 3 memory device on a 16 GT/s UCIe link has an uncorrectable error; the host Root Port isolates it and software resets that hierarchy while the rest of the host runs.

If you break it

Expecting a Retry flit to deliver viral in 68B mode: none arrives.

Check it in the spec
  • SpecViral and error isolation text §2.3.2, p.55–56
Streaming§2.4 p.56 · §3.3.3 p.76

Streaming never uses Protocol ID 00b

In Streaming flit formats the Protocol Layer fills only Protocol ID bits [7:6] of the flit header and must never set 00b.

Why

00b marks an Adapter NOP flit, which the receiving Adapter drops. The other three values are free for vendor use, for example to tag message classes.

Real-time example

A vendor uses 01b for data and 10b for control messages of its accelerator protocol.

If you break it

Flits sent with 00b vanish at the receiver: silent data loss.

Check it in the spec
  • SpecProtocol ID rule §3.3.3, p.76 · §3.3.4, p.80 · Table 3-5
Streaming§2.5 p.57

Management Transport: no 68B

Management Transport over mainband may use Raw or any 256B format, never 68B.

Why

Management flits carry fields (for example the credit return DWORD) at fixed byte positions defined only for the 256B layouts. The 68B format has no room for them.

Real-time example

Format 3 Management flits put the credit-return DWORD in bytes 238–241.

If you break it

Negotiating Management Transport with 68B is an illegal combination; either side may take the link to LinkError.

Check it in the spec
  • SpecFormat restriction §2.5, p.57
  • SpecCRD byte positions §3.3.3, p.76–77
  • SpecIllegal combo → LinkError §3.4, p.87
Streaming§2.1.1 p.53 · §2.2.1 p.54

Raw is for Retimers, and they should count errors

In Raw Format the Protocol Layer keeps its own CRC, retry and FEC. Retimers are strongly recommended to check and count errors using the protocol's FEC parity or CRC.

Why

Across a Retimer, the off-package link dominates errors. End-to-end protocol protection covers both links, and error counts at the Retimer show which link is misbehaving.

Real-time example

A rack-scale CXL link through two Retimers shows replays; the Retimers' counters show all errors on the cable, none on either UCIe link.

If you break it

Retimers that do not count errors leave debug blind to which segment is bad.

Check it in the spec
  • SpecRaw format intent and recommendation §2.1.1, p.53 · §2.2.1, p.54

10 · Test yourself

How is PCIe Non-Flit Mode carried over UCIe? Basic

Using the CXL.io 68B flit formats (Format 2), only when the negotiated maximum data rate is ≤ 32 GT/s.

Spec§2.1.3, p.53

Which format is mandatory for CXL 256B Flit Mode? Basic

Standard 256B Start Header (Format 4). Latency-Optimized formats are strongly recommended in addition.

Spec§2.2.3, p.55 · Table 3-7

Which DLLPs are dropped for PCIe and CXL.io over UCIe? Intermediate

PM and Link Management DLLPs in all modes; Ack/Nak as well (Non-Flit and CXL.io). Other DLLPs such as flow-control updates remain.

Spec§2.1.2–2.1.3, p.53 · §2.2.2, p.54 · §2.3.2, p.55

What extra space does Format 6 give CXL? Intermediate

4 more TLP bytes for CXL.io; a 14-byte H-slot between slots 7 and 8 for CXL.cachemem.

Spec§2.2.2, p.54

How does lp_corrupt_crc contain viral without delaying normal flits? Advanced

The Adapter corrupts the CRC of the marked flit (XOR 138Eh recommended) so the receiver rejects it, and overwrites that flit in the retry buffer with the next flit, which carries viral. The receiver's Nak causes a replay that delivers the viral flit instead.

SpecTable 10-3, p.540

A CXL 3.0 device and a CXL 2.0-only device at a 64 GT/s maximum rate: what happens? Advanced

CXL 2.0 above 32 GT/s is not supported, so there is no common CXL mode at that rate. The link must train with a maximum rate ≤ 32 GT/s, where CXL 68B is mandatory for both.

SpecTable 2-1, p.53
