UCIe FDI Field Guide

The Flit-aware Die-to-Die Interface is the contract between a protocol controller and the UCIe Adapter. This guide covers why it exists, where it sits, how one wire-level Valid frame becomes one FDI beat, the rules it obeys and the reason behind each one, and what its wires actually do cycle by cycle during bring-up, traffic, CRC replay, power management, retrain and errors.

1 · Why FDI exists

Every FDI rule traces back to one of four pressures. Once you know which one a rule serves, the rule is easy to remember.

Interoperability

Mix IP from different vendors

A PCIe or CXL controller from one vendor must drop onto an Adapter and PHY from another. The spec fixes the handshakes at the boundary so integration is wiring, not redesign. It also says outright that a common interface makes Bus Functional Models consistent, because post-silicon interop testing is expensive.

Spec§1.1.4 Interfaces, p.44

Flit awareness

The Adapter owns reliability, the protocol owns meaning

CRC, retry, NOP insertion and DLLP packing live in the Adapter. The Protocol Layer hands over flits and never sees a replay. FDI adds the wires that make this split work: stream IDs, pl_flit_cancel, lp_corrupt_crc and a DLLP side channel that bypasses the retry buffer.

Spec§1.1.2, p.43 · Table 10-3, p.540–542 · §10.2.4.1, p.550

Latency

Nothing extra in the critical path

Received flits are forwarded before CRC finishes, with a one-cycle cancel if it fails. The receive path has no backpressure, so there is no ready signal to close timing on. The receiver is opened before the slow sideband handshake completes, so the first flit is never dropped.

Spec§10.2.5, p.551 · §10.2.2, p.547 · §10.2.7, p.552–553 · Table 1-4, p.49

Power

Either side may gate its clocks

Two four-phase wake handshakes let each side sleep in Reset, LinkReset, Disabled and PM, and guarantee that no state change, register packet or error pulse is lost while the other side is asleep. This is why so many FDI rules mention pl_clk_req.

Spec§10.2.3, p.547–549

Background outside the spec: FDI and RDI descend from Intel's LPIF (Logical PHY Interface), used between CXL/PCIe link layers and the logical PHY, which is why the names lp_irdy, pl_trdy, pl_state_sts and stallreq/stallack look familiar to CXL controller engineers. The Streaming protocol path is how vendor fabrics ride UCIe; Arm's CHI C2C is one published example.

6 · The four handshakes

All four follow the same four-phase pattern: request rises, acknowledge rises, request falls, acknowledge falls. Each needs at least one flop between request and acknowledge, so there is never a combinational loop across the interface.

7 · Why each rule exists, with real-time examples

Each card gives an FDI rule, the reason behind it, a worked example with real numbers, and what breaks when a design ignores it. Numbers assume an x64 Advanced Package module at 16 GT/s and a 64-byte FDI at 2 GHz unless the card says otherwise.

Clocking & width§10.3.1 p.561 · §4.1.1 p.98

Wide and slow: 64 bytes at 2 GHz, not 1 bit at 16 GHz

FDI moves NBYTES per lclk cycle. Everything that runs at the bit rate stays inside the PHY.

Why

This is the mainband clock's trade taken one level further. Logic that decodes headers, computes CRC and arbitrates between streams cannot close timing at the bit rate, and dynamic power grows with frequency (P ≈ C·V²·f). A wide, slow path puts the bandwidth into on-die wires, which are cheap, instead of into frequency, which is not.

Real-time example

Each lane moves 16 bits per nanosecond, so in one 0.5 ns cycle of a 2 GHz lclk it delivers 8 bits: one byte, exactly one 8-UI Valid frame. Sixty-four lanes give 64 bytes, one FDI beat. A 256B flit is 4 beats, 2 ns, the same 2 ns it occupies on the wire as 32 UI.

If you break it

A 32-byte FDI at 2 GHz on that link caps it at 50% utilisation, however much traffic the Protocol Layer has.

Clocking & width§10.2.2 p.547 · Table 1-4 p.49

One clock domain across the interface

Both sides of FDI run on lclk and share one reset source. Clock crossings go inside a block, never at the boundary.

Why

FDI's rules are counted in lclk cycles: the cancel lands exactly one cycle after a flit's last beat, every request waits at least one cycle for its acknowledge, a request sits at NOP for at least one clock. None of that can be exact across an asynchronous boundary. Latency is the other reason: the target is ≤ 2 ns for Adapter plus PHY, transmit plus receive, at 16 GT/s.

Real-time example

A dual-clock FIFO with two-flop synchronisers typically costs 2–3 cycles per crossing; at 2 GHz, 3 cycles is 1.5 ns, three quarters of the budget. So a controller whose core runs at 1.6 GHz crosses to lclk inside the Protocol Layer, where that latency is its own to spend. The one exception follows the same logic: with Management Transport over the sideband, the cfg signals may sit on a separate always-available Mgmt_clk, so management keeps working while lclk is off.

If you break it

A crossing FIFO inside the Protocol Layer sized for average throughput overflows, because the receive path has no backpressure.

Check it in the spec

Clocking & width§10.2.1 p.547

Zero means idle

FDI has no reset wire. Every output drives 0 coming out of reset; only tied-off stream IDs are exempt.

Why

Reset release is routed across the SoC and can reach the two sides a few cycles apart. With all-zero outputs, a block that wakes first sees exactly what an idle partner looks like: lp_state_req 0000 is NOP, pl_state_sts 0000 is Reset, and every valid, stall, wake and clock request is low.

Real-time example

The Adapter leaves reset 3 cycles before the Protocol Layer. For those cycles it samples NOP with lp_irdy low and does nothing. When the Protocol Layer wakes it reads Reset with pl_inband_pres low and simply waits. No extra "both sides are out of reset" synchronisation is needed.

If you break it

A Protocol Layer that drives Active (0001) straight out of reset never produces the NOP→Active edge the Adapter waits for, and the link stays in Reset.

Check it in the spec
  • SpecEvery output drives 0 out of reset; tied-off stream IDs excepted §10.2.1, p.547

Clocking & width§10.3.1 p.559–562

Recommended bus widths, fixed byte order

In Flit mode NBYTES is strongly recommended, not required, to be 64, 128, 256 or 512. A width of 512 or more should be a multiple of 256 and is meant only for a four-module Advanced Package link at 16 GT/s or higher. In Raw format NBYTES is vendor-defined. Flit byte 0 always sits on FDI byte 0.

Why

Every Flit-mode format moves in 256-byte units. A width that divides 256, or is a multiple of it, keeps every flit boundary on a cycle boundary, so per-cycle signals such as pl_flit_cancel and lp_corrupt_crc always point at one flit. The fixed byte order makes module count, lane reversal and lane repair invisible above RDI; MMPL and the PHY handle them.

Real-time example

On a 96-byte bus a 256B flit takes 2⅔ beats, so the end of one flit and the start of the next share a beat: the Adapter needs a rotator, and a cancel in that cycle no longer names one flit. In the other direction, a design that ships first with one x64 module (64B FDI) and later with four (256B FDI) keeps the same Protocol Layer byte order; only NBYTES changes. At the top end, four x64 modules at 64 GT/s move 2048 GB/s, which needs 1024 bytes per cycle at 2 GHz: above 512 and still within the recommendation, because it is a multiple of 256 on a four-module Advanced Package link.

If you break it

Odd widths add shifting logic and pipeline stages to the latency-critical path.

256B formats leave holes; 68B format needs shifting

In 256B formats the Protocol Layer passes all 256 bytes, with 0 in the bytes reserved for the Adapter. In 68B format it passes only the 64-byte payload.

Why

In a 256B flit the Adapter fills the flit header, DLP and CRC bytes in place: nothing moves, and FDI and RDI carry the same number of bytes. In 68B format the Adapter adds a 2-byte header and a 2-byte CRC to every 64 bytes, so the RDI stream is longer than the FDI stream and shifts by 4 bytes per flit.

Real-time example

A CXL 68B stream at full link rate with equal FDI and RDI widths: 16 beats of payload become 16 × 68 = 1088 bytes, 17 RDI beats, so pl_trdy drops about one cycle in seventeen (≈ 6%). When the stream pauses, the Adapter closes it with a PDS flit header and zero padding to a 256-byte boundary, including at least two all-zero 64-byte chunks, so the receiver can reset its byte shifter.

If you break it

A receiving Protocol Layer that does not ignore the Adapter-reserved bytes of a 256B flit treats CRC and DLP bits as payload.

Check it in the spec

Two qualifiers: lp_irdy warns, lp_valid delivers

lp_irdy means "I may have data"; lp_valid means "this beat is data". A beat moves only when lp_irdy, lp_valid and pl_trdy are all high.

Why

The extra signal is an early warning. The lower layer may clock-gate its transmit path between bursts, and seeing lp_irdy first gives it time to ungate and raise pl_trdy before beat 0 arrives. The spec draws this on RDI (Figure 10-4, lp_irdy two cycles ahead of lp_valid); FDI's lp_irdy has the same meaning.

Real-time example

An Adapter whose transmit path needs 2 cycles to ungate. The Protocol Layer raises lp_irdy 2 cycles early, pl_trdy is already high when beat 0 arrives, and the first flit leaves without a bubble.

If you break it

Raising both together into a gated Adapter costs 2 cycles at every burst start: 1 ns at 2 GHz, half the Adapter + PHY latency target.

Tx path§10.2.4 p.549

No bubbles inside a transmitted flit

From a flit's first beat to its last, lp_valid and lp_irdy stay high. Only pl_trdy may pause the transfer.

Why

It lets the Adapter cut through: beat 0 can head for RDI, with the CRC under way, while beat 1 is still arriving. The PHY makes the matching promise one layer down: while the Adapter streams without gaps, the PHY keeps Valid frames back to back on the wire.

Real-time example

Store-and-forward of one 256B flit on a 64-byte bus means waiting for 4 beats, 2 ns at 2 GHz. That is the entire Adapter + PHY latency target spent before the first bit leaves the die.

If you break it

The Adapter must either buffer, costing latency, or open a gap inside its own RDI stream. In 68B mode a mid-stream gap without a PDS breaks the receiver's byte alignment, so expect corrupted flits on the far side.

Check it in the spec

Tx path§10.2.4 p.549

pl_trdy may drop at any time

The Protocol Layer may assume nothing about when pl_trdy falls or for how long.

Why

The Protocol Layer is not the only source of traffic. The Adapter also sends replays, NOP flits, inserted parity bytes and 68B header bytes, and it has to respect Retimer credits and the link's current speed and width.

Real-time examples
  • Runtime parity with N = 4: 256 bytes inserted every 256 KB, so pl_trdy drops 4 cycles in every 4096 on a 64-byte FDI.
  • A replay of 10 flits: 40 beats in which the link carries old flits.
  • Speed degrade from 32 to 24 GT/s with an FDI sized for 32 GT/s: pl_trdy high about 75% of the time.
  • Standard x16 degraded to x8: about 50%.
  • Retimer credits used up: each credit covers 256 bytes, and pl_trdy waits until credits return.
If you break it

A Protocol Layer that schedules on an assumed pl_trdy pattern loses bandwidth or deadlocks on the first replay.

Tx pathTable 10-3 p.540

lp_corrupt_crc: poison a flit that has already left

For CXL.cachemem in UCIe Flit mode, the Protocol Layer can make the Adapter corrupt the CRC of the flit it is sending, by XOR with syndrome 138Eh.

Why

Beats already sent cannot be recalled. A corrupted CRC makes the receiver drop the flit through its normal error path, with no new message type. The Adapter then overwrites that flit in its Tx retry buffer with the next flit from the Protocol Layer, which carries the viral indication, so a replay can never resend the bad data. The syndrome is chosen so no 1-bit or 2-bit error aliases to it.

Real-time example

A CXL.mem read returns data whose uncorrectable ECC error is flagged only as the last beat goes out. The Protocol Layer asserts lp_corrupt_crc with that beat. The far Adapter sees a CRC error and asks for a replay, and the replay delivers the viral flit. Containment costs one flit time plus one replay round trip.

If you break it

Without it, the only fast option is LinkError, which takes the whole link down for at least 16 ms.

Check it in the spec

Tx path§10.2.4.1 p.550

DLLPs travel beside the flits, not in the retry buffer

PCIe and CXL.io DLLPs use lp_dllp and pl_dllp, bypass the retry buffer and ignore pl_trdy. The Adapter keeps only the newest credit DLLP of each type per virtual channel.

Why

A credit update states the current credit total, so a newer one makes an older one worthless, and replaying a stale one is pointless. Keeping DLLPs out of the retry buffer lets credits flow during a replay: the Adapter drops them into DLP bytes 2–5 of whichever flit leaves next, new or replayed.

Real-time example

During a 10-flit replay the Protocol Layer issues a posted-credit UpdateFC twice. The Adapter discards the first, keeps the second and sends it in the next available flit. On receive, all-zero DLP bytes are a NOP DLLP and are not forwarded.

If you break it

DLLPs only leave inside flits. A PCIe controller with no TLPs that also stops sending NOP flits strands its credit updates on-die, and the far side stalls waiting for credits on an idle link.

Check it in the spec

Rx path§10.2.2 p.547 · §10.2.4 p.550

No backpressure on the receive path

Whenever pl_valid is high the beat is taken. There is no ready signal back to the Adapter.

Why

The protocols above already do flow control: PCIe and CXL credits guarantee the receiver has room for everything the far side sends, so a second, link-level ready would be redundant. 64 lanes × R Gb/s ÷ 8 = 8R GB/s. The 16 and 32 GT/s rows match the spec's own examples (§10.3.1, p.561); the other rows are derived. In Flit mode the spec strongly recommends, but does not require, NBYTES of 64, 128, 256 or 512. Widths of 512 or more should be multiples of 256 and only for a four-module Advanced Package link at 16 GT/s or higher, and in Raw format NBYTES is vendor-defined (§10.3.1 implementation note, p.562). Widths that do not line up with the 256B flit add shifting logic. A Standard x16 module carries a quarter of these rates.

Latency budget. Table 1-4 sets a target of ≤ 2 ns for Adapter plus PHY, transmit plus receive, at 16 GT/s, not counting the time to accumulate bits. At a 2 GHz lclk that is four cycles for both dies together. The Tx, Rx and clocking cards in section 7 show which FDI rules exist to protect it.

Energy budget. The same table targets 0.3 pJ/bit (0.5 V) to 0.6 pJ/bit (0.7 V) for an Advanced Package link at 16 GT/s, measured from FDI to the bumps and back to FDI on the far die. 10 · Verification

An FDI agent should be able to act as either the Protocol Layer or the Adapter, so the same component serves a controller-only DUT, an Adapter-only DUT and a full stack.

Assertions

  • No gap in lp_valid/lp_irdy between a flit's first and last chunk. §10.2.4, p.549
  • pl_trdy high only in Active, or during a LinkError stall drain. Table 10-3 (pl_trdy), p.541
  • pl_flit_cancel is one cycle wide and lands exactly one cycle after a last chunk. Table 10-3 (pl_flit_cancel), p.542
  • Each four-phase handshake: order, ≥1 cycle request-to-acknowledge, request falls before acknowledge. §10.2.3.1–10.2.3.2, p.547–548 · §10.2.7, p.552 · §10.3.2, p.563
  • lp_valid and lp_irdy low while lp_stallack is high. §10.3.2 rule 6, p.563
  • Both rx_active signals low before status leaves Active (LinkError excepted, but low before LinkError exits). §10.2.7 rules 5 and 7, p.553
  • Sideband Rsp.Active sent only after pl_rx_active_req = lp_rx_active_sts = 1 was sampled. §10.2.8 step 4, p.554
  • Reset→Active and Retrain(from Active)→Active only after a NOP→Active edge. §10.3.3.1, p.565 · §10.3.3.4, p.567
  • Status never moves Active.PMNAK → L1 or L2. §10.3, p.559 · §10.3.3.2, p.566
  • pl_trainerror holds until LinkError → Reset; LinkError lasts ≥ 16 ms. Table 10-3 (pl_trainerror), p.543 · §10.3.3.7, p.569
  • lp_cfg stable until pl_wake_ack; pl_cfg stable until lp_clk_ack. §10.2.3.1 rule 6 and §10.2.3.2 rule 8, p.548
