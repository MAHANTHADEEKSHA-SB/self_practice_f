AXI Untranslated Transactions & DVM Field Guide

Devices can issue AXI requests with virtual addresses and let a System MMU translate them. That needs two things on the bus: fields that tell the SMMU which translation to use, and messages that tell it when a cached translation is stale. This guide covers the AxMMU signals, translation fault flows, StashTranslation, DVM messages on the AC and CR channels, DVM Sync and Complete, and the Coherency Connection handshake. It includes a DVM message encoder, waveforms, verification checks, interview questions and what changed since Issue H.c.

1 · Why this exists

Isolation

Devices get their own address space

A GPU, NIC or PCIe endpoint works in a virtual (or intermediate physical) address space. The SMMU translates and checks every access, so a device can only reach memory the OS or hypervisor mapped for it.

Spec§A13.1, p.205

One physical space

Translate before the coherent interconnect

Hardware coherency needs a single physical address space, so the SMMU usually sits between the device and the coherent interconnect.

Spec§A13.2, p.206

Which translation?

The request carries its context

The AxMMU signals tell the SMMU which security space, device stream and process the address belongs to, and what to do on a fault. Different requests on one interface can use different translations.

Spec§A13.2–A13.4, p.206–210

Stale TLBs

Page tables change; caches must follow

When software changes a translation table, every TLB that cached the old entry must drop it. DVM messages carry those invalidations to SMMUs, and DVM Sync tells the requester when they have taken effect.

Spec§A13.1, p.205 · §A15.1, p.232

2 · Where it sits

1 · Request

The Manager issues a transaction that uses a VA.

2 · Translate

The SMMU uses a TLB entry, or walks the translation tables in memory. If no translation exists, the walk faults and the agent that maintains the tables must be told.

3 · Forward

The SMMU issues the transaction with the PA for the requesting component.

4 · Translation identifiers and versions

SECSID

Which virtual address space

  • 00 Non-secure, 01 Secure, 10 Realm, 11 reserved.
  • Width 1 without RME, 2 with RME, 0 when the feature is off.
  • Non-secure → PAS must be Non-secure. Secure → Non-secure or Secure. Realm → Non-secure or Realm.

Spec§A13.4.1 and Tables A13.4–A13.5, p.209

SID

Which device context

  • 0–32 bits; maps a request to a translation context.
  • Each address space has its own namespace, so values may repeat across them.
  • Usually low bits from the component, high bits tied off per port; unsupplied bits LOW.
  • PCIe: the Requester ID.

Spec§A13.4, p.209 · §A13.4.2, p.210 · §A13.5, p.212

SSIDV + SSID

Which process within the device

  • 0–20 bits, with its own valid bit.
  • SSID must be 0 when SSIDV is LOW.
  • SubstreamID 0 is not the same as no substream.
  • PCIe: the PASID; SSIDV follows the PASID prefix.

Spec§A13.4.3, p.210 · §A13.5, p.212

StashTranslation · AWSNOOP 0b01110

Warm the translation cache

  • AW and one B; no write data. AWSNOOP may be 4 or 5 bits wide.
  • Virtual address: cache the page table entry. Physical address (MMUVALID LOW, RME only): cache the Granule Protection Table entry.
  • No stash target; AWATOP and AWTAGOP zero; any legal AWCACHE/AWDOMAIN.
  • Must not share an ID with outstanding non-StashTranslation writes.
  • OKAY means accepted, not stashed.

Spec§A13.9, p.219

UnstashTranslation · AWSNOOP 0b10001

This entry won't be needed again

  • Same shape as StashTranslation, but AWSNOOP must be 5 bits wide.
  • AWID unique in flight; AWIDUNQ asserted if present.
  • Property UnstashTranslation_Transaction; a Manager with True can't connect to a Subordinate with False.
  • OKAY means accepted, not deallocated.

Spec§A13.10 and Tables A13.15–A13.16, p.220–221

7 · DVM messages

Six message types: TLB Invalidate, Branch Predictor Invalidate, Physical and Virtual Instruction Cache Invalidate, Sync and Hint. They only ever invalidate read-only structures, so invalidating more than asked is always functionally correct, only slower.

Transport
  • Request on AC (Subordinate → Manager), response on CR.
  • The payload rides on ACADDR, plus 4-bit ACVMIDEXT from DVM_v8.1.
  • A message with an address takes two transfers, back to back; the sender must not need the first response before sending the second.
  • CR only acknowledges receipt, in order; there is no success or failure.

Spec§A15.4–A15.4.1, p.248–250

Handshake rules
  • ACVALID must not wait for ACREADY; CRVALID must not wait for CRREADY.
  • CRVALID only after the AC handshake.
  • Credited transport: one Resource Plane, no shared credits, and the response still waits for a request.

Spec§A15.4.2–A15.4.3, p.250

Support
  • DVM_Message_Support: Receiver or False (default). Receiver needs Shareable_Transactions.
  • Versions DVM_v8, v8.1, v8.4, v9.2; each includes the earlier ones. Both ends must match.
  • ADDR_WIDTH limits the VA: 57-bit VA needs at least 48 address bits. Extra address bits received are ignored.

Fields worth knowing

  • Exception: 00 hypervisor and all guests, 01 EL3, 10 guest OS, 11 hypervisor.
  • Security means different things per message type; for TLBI: 00 Realm, 01 Non-secure address from a Secure context, 10 Secure, 11 Non-secure.
  • Stage: 00 both (Armv8+), 01 stage 1, 10 stage 2, 11 GPT.
  • Leaf: invalidate leaf entries only. TTL/TG: hint for the table level holding the leaf.
  • Range (Armv8.4+, with an address): (Num+1) × 2^(5×Scale+1) × granule bytes from the base address.
  • GPT TLBI by PA uses a 4-bit Invalidation Size, 4KB to 512GB; an unaligned PA needs no invalidation.

SpecTable A15.3, p.234–236 · Table A15.6, p.238 · p.242

8-bit and 16-bit ASID and VMID

  • A message doesn't say which size it uses. 8-bit senders drive the upper byte to zero.
  • A 16-bit sender talking to an 8-bit receiver: if the upper byte is non-zero the receiver ignores it and over-invalidates. Correct, but slower.
  • In a mixed system, maintenance should be done by a 16-bit agent.
  • The upper VMID byte travels on ACVMIDEXT and ACADDR[43:40], in different places for one-part and two-part messages.

8 · DVM Sync and Complete

The flow

  1. Sync arrives on AC. The Manager acknowledges on CR, without depending on progress of any AR or AW transaction.
  2. When all earlier invalidations are complete, the Manager sends DVM Complete on AR, after the Sync's AC handshake and in a timely manner, even while more messages and Syncs arrive.
  3. The interconnect answers on R; the read data is not valid.

One Complete per Sync, and no Complete without a Sync.

"Complete" means: for a TLBI, the Manager can no longer use the invalidated translation and every earlier transaction that could have used it has finished. For branch predictor and instruction cache invalidations, the cached copies are gone and can't be accessed.

9 · Coherency Connection

DVM requests arrive at a Manager unasked, so a Manager that powers down must first stop them. SYSCOREQ and SYSCOACK form a four-phase handshake that is safe across clock domains.

Level rules

The Manager changes SYSCOREQ only when SYSCOACK is at the same level. The Subordinate changes SYSCOACK only when SYSCOREQ is at the opposite level.

Leftover Complete

The interconnect may drop SYSCOACK before a DVM Complete it is owed arrives. The Manager must still send that Complete on AR.

AWAKEUP must be asserted to guarantee a SYSCOACK transition. ACWAKEUP should precede ACVALID by a cycle. Credited snoop channels have their own ACTIVATEREQD/ACKD and ASKSTOPD, independent of the connection state.

10 · Why each rule exists, with real-time examples

Untranslated§A13.7 p.217

Virtual and physical requests use different IDs

Requests with AxMMUVALID HIGH and LOW must not share an in-flight ID.

Why

Same-ID transactions must keep their order. A virtual request may wait for a table walk or a stall while a physical one bypasses translation; with a shared ID the SMMU would have to hold the fast one behind the slow one, or reorder illegally.

Real-time example

A DMA engine issues a VA read (ID 3) that misses the TLB, then a PA read. If the PA read also used ID 3, its data would have to wait several hundred cycles for the walk.

If you break it

Out-of-order responses on one ID, or a bypass path blocked behind translation.

Untranslated§A13.4.3 p.210

SubstreamID 0 is not "no substream"

AxMMUSSIDV says whether a SubstreamID exists; when LOW, AxMMUSSID must be 0.

Why

The SMMU picks a different translation context for a stream with substream 0 and for the same stream with none. Without the valid bit the two would be indistinguishable.

Real-time example

A PCIe function sends some requests with a PASID prefix (a user process, shared virtual addressing) and others without (the kernel's DMA mapping). PASID 0 and no PASID use different page tables.

If you break it

Requests translated with the wrong process's tables: a fault at best, a cross-process access at worst.

Sources

Fault flows§A13.6.1 p.215

Don't stall PCIe

Stall flow is not recommended with PCIe; Root Ports should use NoStall.

Why

Resolving a stall needs software, and software may need to reach the same PCIe device (outgoing CPU-to-PCIe traffic) while the device's incoming transaction is stalled in the SMMU. Each waits on the other.

Real-time example

An NVMe drive's DMA write faults and stalls. The fault handler needs to read the drive's registers, but the Root Port can't accept the read until its stalled write moves.

If you break it

Deadlock or a completion timeout on the PCIe link.

Sources

Fault flows§A13.6.4 p.216

TRANSFAULT on every beat, and only for PRI

If one response transfer is TRANSFAULT, all are; it is permitted only for PRI-flow requests.

Why

TRANSFAULT means "nothing happened, ask for the page and retry the whole transaction". A partly completed burst couldn't be retried safely. And only a PRI-capable Manager knows what to do with it; others expect SLVERR or OKAY.

Real-time example

An integrated endpoint's 4-beat read hits an unmapped page: four beats of TRANSFAULT, then a PCIe Page Request, then the same read again.

If you break it

A Manager that treats beat 1 as data and beat 2 as a fault has consumed garbage.

Sources

DVM§A15.5 p.258

The Sync acknowledgement must not wait for traffic

The CR response to a DVM Sync must not depend on progress of any AR or AW transaction.

Why

The interconnect may be holding the Manager's reads or writes until the DVM message is acknowledged, or other messages are queued behind it on the ordered AC channel. If the acknowledgement waited for those transactions, neither could move. The slow part (draining old traffic) is what DVM Complete is for.

Real-time example

An SMMU with 12 reads outstanding gets a Sync. It answers on CR next cycle, and sends DVM Complete on AR only after those 12 reads finish.

If you break it

A system-wide hang during a TLB shootdown, usually under load.

DVM§A15.4 p.248

Two-part messages are never split up

Both parts are sent as successive transfers, and the sender must be able to send the second without the first's response.

Why

The second part carries no type field: it is just address bits. The receiver knows what it is only because it directly follows a first part with Addr = 1. And requiring the first response before the second would deadlock a receiver that answers only whole messages.

Real-time example

TLBI by VA: first transfer has ASID, VMID and VA[56:45]; the second has VA[44:12]. Use the encoder in section 7 to see both words.

If you break it

The receiver decodes an address as a message type and invalidates the wrong thing, or nothing.

Sources
  • Spec§A15.4, p.248 · Table A15.20, p.252–253

DVM§A15.3 p.234

Over-invalidation is always legal

It is functionally correct to invalidate more entries than a DVM message requires.

Why

TLBs, branch predictors and instruction caches are read-only copies. Dropping an entry only costs a refill. This is what lets simple receivers ignore fields they don't implement.

Real-time example

A small SMMU with no per-ASID tagging treats "TLBI by ASID and VA" as "flush everything". It is slower after each shootdown but always correct.

If you break it

The opposite error, under-invalidation, leaves a device using a mapping the OS has revoked: memory corruption or a security hole.

Sources
  • Spec§A15.3, p.234 · p.238–239
  • Illustrativesmall SMMU
Connection§A15.6.1 p.262

Be ready for messages before SYSCOACK

A Manager must be able to receive DVM messages in the Connect state, though the Subordinate may not send them yet.

Why

SYSCOACK and ACVALID may cross clock domains by different paths. The Manager can see ACVALID before it sees SYSCOACK rise, so it must already be listening.

Real-time example

SYSCOACK passes a 2-flop synchroniser; the AC channel passes an async FIFO that happens to be a cycle faster. The first TLBI lands while the Manager still sees SYSCOACK LOW.

If you break it

The first invalidation after power-up is dropped or hangs the AC channel.

Sources
  • Spec§A15.6.1, p.262 · clarified in Issue L, Table B4.3, p.312
  • IllustrativeCDC structure
ConnectionTable A15.26 p.261

Finish using translations before disconnecting

SYSCOREQ may fall only when every transaction using previously fetched translation data has completed.

Why

Once disconnected, the interconnect treats Syncs as complete for this Manager. If it still had traffic using an old translation, software would be told the mapping is dead while it is still in use.

Real-time example

A display SMMU going idle drains its last frame's reads, flushes its TLB, then drops SYSCOREQ and waits for SYSCOACK before its power domain is switched off.

If you break it

A page is freed and reused while a device is still writing to it.

14 · Verification

Assertions

  • AxMMUSSIDV LOW → AxMMUSSID zero. §A13.4.3, p.210
  • SECSID/PAS pairs and the full combination table. §A13.4.1, p.209 · Table A13.14, p.218
  • AxMMUVALID HIGH → AxTAGOP Invalid; no ID shared between in-flight virtual and physical requests. §A13.7, p.217
  • TRANSFAULT only if the request's flow was PRI, and then on all beats. §A13.6.4, p.216
  • Stash/UnstashTranslation: no W beats, stash target LOW, ID rules. §A13.9–A13.10, p.219–221
  • AC: second part directly follows a first part with Addr = 1; reserved bits zero; ASID/VMID zero when their valid bit is LOW. §A15.4, p.248 · Table A15.3, p.234
  • CRVALID only after an AC handshake; responses counted in order. §A15.4.2, p.250
  • DVM Complete: every field of Table A15.23; exactly one per Sync, none without. §A15.5, p.258–259
  • SYSCOREQ/SYSCOACK four-phase rules; no ACVALID in Disabled or Connect. §A15.6.1, p.261–262

Scenarios and coverage

  • Each fault flow × fault / no fault × read / write; PRI retry after TRANSFAULT; Stall with long latency.
  • Mixed virtual and physical traffic on one interface (v3), including StashTranslation with a PA.
  • Every TLBI row your DVM version supports, one-part and two-part, range and non-range; 8-bit and 16-bit ASID/VMID.
  • Sync while reads and writes are outstanding; several Syncs before the first Complete; messages arriving between Sync and Complete.
  • Back-pressure on ACREADY between the two parts; CRREADY held LOW.
  • Connect and disconnect with a message racing SYSCOACK; disconnect with a Complete still owed; disconnect in the middle of a two-part message.
  • Scoreboard: after DVM Complete, no later downstream request may use a translation invalidated before the Sync.

What is an untranslated transaction, and who translates it? Basic

An AXI request whose address is virtual (or intermediate physical). A System MMU between the Manager and the rest of the system translates it to a physical address, using the AxMMU fields to choose the translation.

Spec§A13.1–A13.2, p.205–206

What do SID and SSID map to for PCIe? Basic

SID is the Requester ID and SSID is the PASID. SSIDV is HIGH when the transaction had a PASID prefix.

Spec§A13.5, p.212

Which channels carry a DVM message, and in which direction? Basic

The request goes on AC from the Subordinate interface (usually an interconnect) to the Manager; the acknowledgement returns on CR. That is the opposite direction to ordinary requests.

Spec§A15.1, p.232 · §A15.4, p.248

Name the four fault flows and what each returns on a fault. Intermediate

Stall: SLVERR, OKAY with RAZ/WI, or a stall, as software configures. ATST: SLVERR. NoStall: SLVERR or OKAY, never a stall. PRI: TRANSFAULT on all beats (or SLVERR if a page request can't help).

Spec§A13.6, p.214–216

What does AxMMUVALID LOW mean, and what is its default? Intermediate

The address is physical and needs no translation; the other AxMMU fields don't apply. The default is 1, so an interface without the signal is treated as always untranslated.

SpecTable A13.2, p.207 · §A13.7, p.217

What is the difference between the CR response to a Sync and DVM Complete? Intermediate

CR only says the Sync was received, and must come without waiting for other traffic. DVM Complete, sent later on AR, says all earlier invalidations have taken effect and every transaction that could have used the old translations has finished.

Spec§A15.5, p.258

Why does a message with an address need two AC transfers, and how does the receiver know? Intermediate

ACADDR isn't wide enough for the control fields, ASID, VMID and a VA of up to 57 bits together. The first transfer has Addr (ACADDR[0]) set, so the receiver knows the next AC transfer is the second part.

Spec§A15.4, p.248 · Table A15.20, p.252–253 · Derived width reasoning

A 16-bit-VMID hypervisor sends a TLBI to an SMMU that implements 8-bit VMIDs. What happens? Advanced

The SMMU ignores VMID[15:8]. If those bits were non-zero it invalidates entries for every VM sharing the low byte: over-invalidation, which is correct but costs performance.

Specp.238–239

The interconnect drops SYSCOACK while the Manager still owes a DVM Complete. Is that legal, and what must the Manager do? Advanced

Legal. The Manager must still send the DVM Complete on AR even though DVM messages are now disabled.

Spec§A15.6.1, p.262

List the constraints on a DVM Complete request. Advanced

ARSNOOP 0b1110, ARADDR 0, INCR, one transfer, ARSIZE = data width or Max_Transaction_Bytes if smaller, Shareable, ARCACHE 0b0010, ARID not shared with an outstanding non-Complete read, and ARCHUNKEN, ARLOCK, ARTAGOP, ARMMUVALID, ARMMUATST, ARMMUFLOW all zero.

SpecTable A15.23, p.259

Compute the range of a TLBI with TG = 4KB, Scale = 1, Num = 3. Advanced

(3+1) × 2^(5×1+1) × 4KB = 4 × 64 × 4KB = 1 MB starting at the base VA.

Specrange formula, p.242 · Derived

Why may a StashTranslation not share an ID with other outstanding writes? Advanced

So there are no ordering constraints between the hint and real writes. A Subordinate that doesn't stash translations can then answer at once without tracking other transactions.
