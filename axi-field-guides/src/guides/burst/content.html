AXI Bursts & Addressing Field Guide

One AXI request describes up to 4 KB of data with a start address and three small fields: Size, Length and Burst. This guide covers how those fields turn into an address and a set of byte lanes for every beat, why WRAP and FIXED exist, the 4 KB rule, narrow, unaligned and byte-invariant transfers, and the write strobes. It includes a burst calculator, step-through waveforms, verification checks, interview questions, and a comparison with AXI3 and AXI4.

1 · Why AXI moves data in bursts

The request fields are small on purpose. Each rule about them protects one of these four things.

Request bandwidth

One address for up to 4 KB

A request carries only the first address, plus attributes. The Subordinate calculates every later address itself. A 256-beat burst costs one request transfer.

Spec§A1.1, p.21 · §A3.1, p.43

Simple decoders

Never cross a 4 KB boundary

A transaction stays inside one 4 KB-aligned block. Address decoders route on whole 4 KB pages, so no transaction can straddle two Subordinates, and a Subordinate only needs a 12-bit incrementer.

Spec§A3.1, p.43 · §A3.1.3, p.45

Caches

WRAP for cache lines

A line fill starts at the word the CPU needs and wraps round the line, so the CPU restarts after the first beat. FIXED does the opposite job: many transfers to one address, for FIFOs.

Spec§A3.1.4, p.47

Any data, any width

Byte lanes, strobes and byte invariance

Narrow, unaligned and mixed-endian accesses all use the same rule: byte k of memory always travels on lane k modulo the channel width. Strobes say which of those bytes a write really changes.

Spec§A3.2.1.1, p.54 · §A3.2.3–A3.2.5, p.55–58

A maximum, not a promise. For reads, Size bytes must be valid per beat; for writes, Size lanes may be active and WSTRB says which really are. Size must not exceed the channel width.

Spec§A3.1.1, Tables A3.1–A3.2, p.43

AxLEN[7:0]: beats − 1
  • Length = AxLEN + 1: 1 to 256.
  • Size × Length is the most bytes the transaction can move; unaligned starts and LOW strobes move fewer.
  • The Manager sends exactly Length W beats; the Subordinate sends exactly Length R beats.
  • WRAP: Length 2, 4, 8 or 16. FIXED: up to 16. INCR: up to 256, within 4 KB.
  • No early termination. Unwanted write beats go out with WSTRB all LOW; unwanted read beats are accepted and dropped.

5 · The address equations

Every Subordinate, interconnect and checker implements these. Size and Length are in bytes and beats; Data_Bytes = DATA_WIDTH / 8; INT() rounds down; N counts beats from 1.

Start_Addr     = AxADDR
Aligned_Addr   = INT(Start_Addr / Size) * Size
Address_1      = Start_Addr
Address_N      = Aligned_Addr + (N - 1) * Size      // INCR, and WRAP before it wraps

Wrap_Boundary  = INT(Start_Addr / (Size * Length)) * Size * Length
if Address_N == Wrap_Boundary + Size * Length:
    Address_N  = Wrap_Boundary                      // this beat
    Address_N  = Aligned_Addr + (N - 1) * Size
                 - Size * Length                    // later beats

// first beat
Lower_Byte_Lane = Start_Addr - INT(Start_Addr / Data_Bytes) * Data_Bytes
Upper_Byte_Lane = Aligned_Addr + (Size - 1)
                  - INT(Start_Addr / Data_Bytes) * Data_Bytes
// later beats
Lower_Byte_Lane = Address_N - INT(Address_N / Data_Bytes) * Data_Bytes
Upper_Byte_Lane = Lower_Byte_Lane + Size - 1
data on DATA[8*Upper_Byte_Lane + 7 : 8*Lower_Byte_Lane]

Container_Size  = Size * Length
INCR: Container = Aligned_Addr  .. Aligned_Addr  + Container_Size
WRAP: Container = Wrap_Boundary .. Wrap_Boundary + Container_Size

Worked example: unaligned INCR

AxADDR 0x1F0B, Size 4, Length 3, 64-bit channel (Data_Bytes 8).

  • Aligned_Addr = 0x1F08.
  • Beat 1: lanes 3 (0x1F0B − 0x1F08) to 3 (0x1F08 + 3 − 0x1F08). One byte.
  • Beat 2: Address 0x1F0C, lanes 4–7.
  • Beat 3: Address 0x1F10, lanes 0–3.
  • Container 0x1F08–0x1F13; bytes moved 1 + 4 + 4 = 9 of a possible 12.

Derived from §A3.1.6, p.50. Try it in the calculator.

Corrected in Issue L. The equation for the beats after a WRAP wraps now reads Aligned_Addr + (N − 1) × Size − Size × Length. H.c wrote Start_Address in the same place. For a legal WRAP the two are equal, because a WRAP start must be aligned to Size.

SpecTable B4.3, p.311 · H.c §A3.4.1, p.A3-51 · Derived equivalence

The pseudocode in one paragraph

Start at the given address. While the address is unaligned, the upper lane is capped at the end of the aligned Size slot. After the first beat, jump to Aligned_Addr + Size, and from then on every beat is aligned. FIXED never moves the address. WRAP resets to the lower wrap boundary when it reaches the upper one.

    7 · Lanes, strobes, endianness and alignment

    The address and Size decide which lanes a beat may use. WSTRB then says which of those bytes a write actually changes.

    Write strobes

    WSTRB[n] covers WDATA[8n+7:8n]

    • While WVALID is HIGH: a byte to be written has its strobe HIGH.
    • Inside the transaction container, any pattern is allowed, including all LOW (that beat writes nothing).
    • Outside the container, every strobe must be LOW.
    • While WVALID is LOW, strobes may be anything; recommended LOW or held. WDATA is recommended 0 where the strobe is LOW.
    • A Manager that only writes full width may omit WSTRB; the Subordinate ties its input HIGH.

    Spec§A3.2.1.1, Tables A3.22–A3.23, p.54

    Narrow transfers

    Size smaller than the channel

    INCR and WRAP move to a different set of lanes each beat, following the address. FIXED reuses the same lanes every beat. Figure A3.2: three 32-bit beats from address 4 on a 64-bit channel use the upper half, then the lower half, then the upper half.

    Spec§A3.2.3, Figures A3.1–A3.2, p.55–56

    Byte invariance

    A byte never changes wires

    The 32-bit value 0x0A0B0C0D stored at address A on a 32-bit channel:

    lane 3 · A+3
    lane 2 · A+2
    lane 1 · A+1
    lane 0 · A
    0x0A
    0x0B
    0x0C
    0x0D

    little-endian: LSB 0x0D at the lowest address

    0x0D
    0x0C
    0x0B
    0x0A

    big-endian: MSB 0x0A at the lowest address

    In both cases the byte at address A rides lane 0. Endianness decides which byte of the value sits at A, not which wire A uses. That is why little- and big-endian structures can share one memory, and why a big-endian-only component needs a conversion function.

    Spec§A3.2.4, Figures A3.3–A3.5, p.56–58

    Unaligned transfers

    Two ways to start mid-word

    • Send the unaligned address in the low address bits, or send an aligned address and clear the leading strobes.
    • Address and strobes must agree.
    • The Subordinate need not take any special action based on alignment information.
    • Only the first beat is unaligned. After it, every beat is aligned (see section 5).
    • WRAP may not start unaligned to Size.

    Spec§A3.2.5, Figures A3.6–A3.7, p.58–60 · §A3.1.4, p.47

    Different address widths. ADDR_WIDTH is 1 to 64 bits (default 32). A component with a smaller address space sits in an aligned window of the larger one. The interconnect adds the high bits on the way out, strips them on the way in, and suppresses transactions outside the window.

    Spec§A3.1.5, Table A3.16, p.49

    8 · Why each rule exists, with real-time examples

    Each card gives a rule, the reason behind it, a worked example, and what breaks when a design ignores it. Numbers assume a 128-bit channel at 1 GHz unless stated.

    Length & 4 KB§A3.1 p.43 · §A3.1.3 p.45

    Never cross a 4 KB boundary

    No transaction may touch bytes on both sides of a 4 KB-aligned boundary. 4 KB is also the largest Size × Length.

    Why

    Address maps assign Subordinates in multiples of 4 KB, the smallest common page size. If no burst crosses 4 KB, the interconnect decodes a burst once, from its start address, and never has to split it between two Subordinates. Inside the Subordinate, burst address logic only has to increment the low 12 bits.

    Real-time example

    A DMA copies 10 000 bytes from 0x8000_0F40 with 64-byte beats. The first burst may go only to 0x8000_0FFF: 192 bytes, 3 beats. Then 0x8000_1000 starts a fresh 4 KB block that can take one 64-beat (4096-byte) burst, and so on.

    If you break it

    The part above the boundary goes to whichever Subordinate the start address decoded to, which may be the wrong one. Or a Subordinate's 12-bit incrementer wraps and overwrites the start of its own page.

    Length & 4 KB§A3.1.2 p.44

    No early termination, ever

    Every component sends or accepts exactly Length beats. Write beats you don't need go out with all strobes LOW; read beats you don't need are accepted and dropped.

    Why

    Every stage on the path (interconnect, width converter, Subordinate) counts beats against AxLEN to find the end of the burst. A shortened burst would leave all of them waiting. Keeping the beat count fixed means "LAST" is never needed to recover state, only to confirm it.

    Real-time example

    A network DMA reads a 16-beat descriptor block but finds after beat 4 that it's an end-of-chain marker. It still takes beats 5–16 at 1 per cycle: 12 ns at 1 GHz. H.c warns that this can lose data from read-sensitive Subordinates like FIFOs, so such Managers must request exactly what they need.

    If you break it

    A Manager that drops WVALID after a "cancel" hangs the W channel for every later write.

    Length & 4 KB§A3.1.2 p.44 · §A4.2.2 p.69

    INCR up to 256 beats, everything else up to 16

    AxLEN is 8 bits, so INCR reaches 256 beats. WRAP is 2, 4, 8 or 16 beats; FIXED at most 16. A Non-modifiable INCR longer than 16 may still be split.

    Why

    Long INCR bursts amortise request overhead for DMA and streaming. WRAP and FIXED stay short because their use cases (cache lines, FIFOs) are short. The AXI3 limit was 16 for everything; the special permission to split long Non-modifiable bursts exists so they can still pass through AXI3 and to protect QoS.

    Real-time example

    A 256-beat burst on a 16-byte channel moves 4 KB in 256 ns at 1 GHz and holds the W channel for all of it. A bridge to an AXI3 Subordinate splits it into sixteen 16-beat bursts, keeping every other attribute.

    If you break it

    WRAP with Length 3 or 32 is illegal; a Subordinate's wrap logic computes a boundary that doesn't exist.

    Sources
    • Spec§A3.1.2, p.44 · §A4.2.2, p.69

    • Derivedtiming
    Burst types§A3.1.4 p.47

    WRAP: aligned start, power-of-two length

    A WRAP start address is aligned to Size and its Length is 2, 4, 8 or 16. The address wraps at the container, which is aligned to Size × Length.

    Why

    Those two rules make Size × Length a power of two and the container naturally aligned, exactly like a cache line. The wrap is then one mask operation on the low address bits, and the first beat can be the one the CPU is waiting for.

    Real-time example

    A 64-byte line on a 128-bit channel, miss on 0x1038: ARADDR 0x1030, Size 16, Length 4, WRAP. Beats 0x1030, 0x1000, 0x1010, 0x1020. The CPU restarts after the first beat; a DDR controller can map the burst to one BL8 access with the same critical-chunk order.

    If you break it

    An unaligned WRAP start gives a first beat that straddles the wrap point. Subordinates handle it differently, so the data ends up in different places.

    Sources
    • Spec§A3.1.4, p.47
    • Backgroundcritical-word-first, DDR burst order
    Burst types§A3.1.4 p.47–48

    FIXED: one address, one set of lanes

    The address and active lanes are the same every beat, Length ≤ 16, and only WriteNoSnoop/ReadNoSnoop may use FIXED. A Subordinate may refuse FIXED altogether (Fixed_Burst_Disable).

    Why

    FIXED exists for addresses with side effects, like pushing into a FIFO data register. Such accesses never mean anything to a cache, so FIXED has no place in the coherent and cache-maintenance opcodes. Since few Managers use it, Issue K let Subordinates declare it unsupported and save the logic.

    Real-time example

    A crypto engine's input FIFO at 0x4000_0040. A DMA writes 16 × 4-byte beats with FIXED, one request instead of sixteen.

    If you break it

    FIXED to a cacheable or Shareable opcode, or to a Subordinate that declared Fixed_Burst_Disable, is an illegal combination. A downsizer that doesn't special-case FIXED will increment the address it should hold.

    Sources
    • Spec§A3.1.4, Tables A3.13–A3.14, p.47–48
    • Illustrativecrypto FIFO
    Burst types§A3.1.8 p.52

    Regular transactions

    Regular: Length 1, 2, 4, 8 or 16; full width if Length > 1; INCR or WRAP; INCR aligned to its container, WRAP aligned to Size.

    Why

    Most real traffic is cache lines and aligned power-of-two blocks. A Subordinate that only ever sees those can drop the unaligned, narrow and FIXED logic. The property makes that a declared, checkable contract instead of an assumption.

    Real-time example

    A last-level cache port that only accepts 64-byte aligned lines declares Regular_Transactions_Only = True. Connecting a DMA that issues unaligned 7-beat bursts directly to it is "not compatible", and the spec warns of data corruption or deadlock.

    If you break it

    Corruption or deadlock. An interconnect must convert non-Regular traffic before such a Subordinate.

    Lanes & strobes§A3.2.1.1 p.54

    Strobes free inside the container, LOW outside

    Any strobe pattern is allowed within the transaction container, including all LOW. Outside the container every strobe must be LOW.

    Why

    Sparse writes (packing, read-modify-write avoidance) need arbitrary strobes. But bytes outside the container belong to addresses the request never named, possibly in another Subordinate's region after width conversion. Writing them would corrupt memory nobody asked to touch.

    Real-time example

    A 4-byte write to 0x1006 on a 64-bit channel: lanes 4–7 form the Size slot (0x1004–0x1007). WSTRB 0x40 or 0xC0 is fine. WSTRB 0x0F would write 0x1000–0x1003, outside the container: illegal.

    If you break it

    Silent corruption of neighbouring bytes, often only visible after a width converter remaps lanes.

    Sources
    • Spec§A3.2.1.1, p.54 · Table B4.2, p.309
    • Derivedlane arithmetic
    Lanes & strobes§A3.2.4 p.56

    Byte invariance

    A byte transfer to a given address always uses the same data wires, whatever the endianness or size of the access it is part of.

    Why

    A network packet can have a little-endian header and a big-endian payload in the same buffer. If lanes moved with endianness, a big-endian payload write could corrupt the header. With byte invariance only the producer's interpretation of the bytes changes, never the memory layout.

    Real-time example

    A big-endian DSP writes 0x0A0B0C0D to 0x100; a little-endian CPU reads byte 0x100 and gets 0x0A. Both used lane 0 for address 0x100; the DSP's bridge did the byte swap inside the DSP, not on the bus.

    If you break it

    A component that swaps lanes on the bus for big-endian accesses breaks every other agent's view of memory.

    Sources
    • Spec§A3.2.4, p.56–58
    • IllustrativeDSP example
    Lanes & strobes§A3.1.1 p.43

    Size is a ceiling on lanes, not a byte count

    For reads, Size bytes per beat must be valid. For writes, Size lanes may be active; strobes pick the bytes. Size never exceeds DATA_WIDTH.

    Why

    Reads have no strobes, so the Manager can only say "give me this slot". Writes have strobes, so Size bounds the slot and strobes refine it. A beat can't use lanes that don't exist, hence the cap.

    Real-time example

    A 64-bit Manager reading a 32-bit register at 0x2004 issues ARSIZE 4 bytes. The Subordinate returns valid data on lanes 4–7; lanes 0–3 should be 0 (recommended), and the Manager ignores them.

    If you break it

    AxSIZE wider than the channel happens after careless width conversion. A Subordinate that computes lanes with it wraps into the wrong lanes.

    Sources
    • Spec§A3.1.1, p.43 · §A3.2.2, p.55
    Addresses§A3.2.5 p.58

    Unaligned: address and strobes must agree

    An unaligned start can be signalled by low address bits or by an aligned address with leading strobes LOW; the two must be consistent. Subordinates need not act on alignment.

    Why

    Memories write by strobe, not by address bits. Allowing both encodings lets a simple Manager always send aligned addresses. Requiring consistency means a Subordinate that does look at address bits (for example to compute the next beat) never gets contradictory information.

    Real-time example

    memcpy of 13 bytes from 0x3003 on a 32-bit channel: AWADDR 0x3003, Size 4, Length 4. First beat WSTRB 1000 (0x3003), then 0x3004–0x300F full. Equivalent: AWADDR 0x3000 with the same strobes.

    If you break it

    AWADDR 0x3003 with WSTRB 1111 on beat 1 tells two stories; a Subordinate that trusts strobes writes 0x3000–0x3002, which the request never named.

    Sources

    Addresses§A3.1.5 p.49

    Smaller address spaces sit in windows

    A component with fewer address bits lives in an aligned window of the larger space. The interconnect adds high bits outbound, strips them inbound, and suppresses transactions outside the window.

    Why

    A 32-bit peripheral subsystem and a 48-bit CPU share one system. Without a defined rule, each bridge would invent its own mapping, and an access outside the window could alias onto a real register.

    Real-time example

    A 32-bit DMA in a 40-bit system is placed at window 0x40_0000_0000. Its outgoing 0x8000_0000 becomes 0x40_8000_0000. An incoming access to 0x12_0000_0000 is suppressed rather than truncated to 0x0000_0000.

    If you break it

    Truncation instead of suppression aliases a stray access onto real memory: a security problem as well as a bug.

    Sources
    • Spec§A3.1.5, p.49
    • Illustrativewindow address
    Properties§A3.1.3 p.45

    Max_Transaction_Bytes: a smaller promise than 4 KB

    A Manager declares that Size × Length never exceeds X and never crosses an X boundary (64 to 4096). A Manager with a larger value than its Subordinate is not compatible.

    Why

    Many Managers only ever issue cache lines. An interconnect that stripes memory across channels at 256 B granules would otherwise have to split any burst that crosses a stripe. Knowing the Manager stays within 256 B lets it skip the splitter entirely.

    Real-time example

    A CPU port with Max_Transaction_Bytes 64 connects to an HBM fabric that interleaves channels every 256 bytes. No request can straddle two channels, so routing is a decode of address bits [10:8].

    If you break it

    A Manager declaring 64 that issues a 128-byte burst lands half its data in the wrong channel.

    Sources
    • Spec§A3.1.3, Tables A3.6–A3.7, p.45
    • IllustrativeHBM striping
    Properties§A3.1.4 p.47

    Wrap_CLS_Modifiable

    When True, every WRAP must be exactly cache-line sized and Modifiable (AxCACHE[1] = 1). New in Issue L.

    Why

    Arbitrary WRAP sizes are hard to convert across data widths or into protocols like CHI that think in cache lines. If WRAP is always a full Modifiable line, a bridge can freely turn it into any equivalent line access.

    Real-time example

    An AXI-to-CHI bridge with this property set treats every WRAP as a 64-byte line read with critical-chunk order, without a fallback path for 8-byte Non-modifiable WRAPs.

    If you break it

    A Manager without the guarantee connected to a Subordinate that requires it is not compatible (Table A3.12). A wrapping AtomicCompare is exempt.

    Sources

    DMA burst generation

    A DMA engine's address generator splits a copy into bursts that respect three limits at once:

    • The next 4 KB boundary: bytes_to_boundary = 4096 − (addr mod 4096). §A3.1, p.43
    • The Subordinate's Max_Transaction_Bytes boundary, if smaller. §A3.1.3, p.45
    • Its own buffer space for outstanding data. §A2.6, p.41

    Typical sequence: one short unaligned head burst to reach alignment, full-size bursts, then a tail. Many DMAs also stop each burst at a 64-byte line boundary to help caches downstream.

    12 · Verification

    Two things to build: a reference model of §A3.1.7 that predicts every beat's address and lanes, and constraints that generate legal, nasty requests.

    Assertions

    • AxBURST ≠ 0b11. Table A3.9, p.46
    • WRAP ⇒ Length ∈ {2, 4, 8, 16} and AxADDR aligned to Size. §A3.1.4, p.47
    • FIXED ⇒ Length ≤ 16; and not issued if Fixed_Burst_Disable. §A3.1.4, p.47–48
    • 2^AxSIZE ≤ DATA_WIDTH/8. §A3.1.1, p.43
    • INCR: AxADDR[ADDR_WIDTH-1:12] == (Aligned_Addr + Size × Length − 1)[ADDR_WIDTH-1:12]. §A3.1, p.43
    • Size × Length ≤ Max_Transaction_Bytes and no MTB-boundary crossing. §A3.1.3, p.45
    • W beat count == AWLEN + 1 with WLAST on the last only; same for R. §A3.1.2, p.44
    • WSTRB ⊆ legal lanes of the beat (from the model). §A3.2.1.1, p.54
    • FIXED: active lane set identical on every beat. §A3.1.4, p.47
    • Regular_Transactions_Only ⇒ every request is Regular. §A3.1.8, p.52

    SVA sketches

    // 4 KB for INCR: first and last byte in the same page
let last_byte(a, s, l) = ((a >> s) << s) + ((l + 1) << s) - 1;
a_4k: assert property (@(posedge ACLK) disable iff (!ARESETn)
  AWVALID && AWBURST == INCR |->
  (AWADDR[ADDR_W-1:12] ==
   last_byte(AWADDR, AWSIZE, AWLEN)[ADDR_W-1:12]));

// WRAP legality
a_wrap: assert property (@(posedge ACLK) disable iff (!ARESETn)
  ARVALID && ARBURST == WRAP |->
  ARLEN inside {1, 3, 7, 15} &&
  ((ARADDR & ((1 << ARSIZE) - 1)) == 0));

// strobes stay inside the beat's legal lanes (mask from the model)
a_strb: assert property (@(posedge ACLK) disable iff (!ARESETn)
  WVALID |-> ((WSTRB & ~legal_mask) == 0));

// beat count
a_wlast: assert property (@(posedge ACLK) disable iff (!ARESETn)
  WVALID && WREADY |-> (WLAST == (wbeat == cur_awlen)));

    Constraints and scenarios that find bugs

    • Bursts ending exactly at 0x…FFF, and 1 byte past it (negative test). §A3.1, p.43
    • Unaligned starts at every offset within Size and within the channel. §A3.2.5, p.58
    • Narrow Size on every channel width, including Size 1 on 1024-bit. §A3.2.3, p.55
    • WRAP starting at every legal slot of the container, all four lengths. §A3.1.4, p.47
    • FIXED unaligned (lanes from the aligned formula on every beat). §A3.1.7, p.51
    • Write beats with all strobes LOW, at the start, middle and end. §A3.2.1.1, p.54
    • Length 256 INCR, and Length 1 with every Size. Table A3.4, p.44

    Functional coverage

    • AxBURST × AxSIZE × length bins (1, 2, 3–15, 16, 17–255, 256).
    • Start offset within Size × within channel × burst type.
    • WRAP: wrap position (beat at which the wrap happens) × Length.
    • Distance from the burst end to the next 4 KB boundary: 0, 1 to Size, larger.
    • Strobe patterns: full, partial, sparse, all LOW, per beat position.
    • Regular vs not Regular; Max_Transaction_Bytes boundary distance.

    13 · Test yourself

    DV-interview style, basic to advanced. Use the calculator to check your arithmetic.

    AWLEN is 0x0F. How many beats is that, and which burst types can use it? Basic

    16 beats (Length = AxLEN + 1). All three: INCR (1–256), WRAP (2, 4, 8, 16) and FIXED (≤ 16).

    SpecTable A3.4, p.44 · §A3.1.4, p.47

    Why can't an AXI transaction cross a 4 KB boundary? Basic

    So a transaction can never span two Subordinates (address maps allocate at 4 KB granularity) and so a Subordinate's address incrementer is bounded to 12 bits. 4 KB is also the maximum Size × Length.

    Spec§A3.1, p.43 · §A3.1.3, p.45

    What are the rules for a WRAP burst, and why does WRAP exist? Basic

    Start aligned to Size; Length 2, 4, 8 or 16; the address wraps at Wrap_Boundary + Size × Length back to Wrap_Boundary, which is the start aligned to Size × Length. It exists for cache line accesses: critical word first, then the rest of the line.

    Spec§A3.1.4, p.47 · §A3.1.6, p.50

    A Manager wants to stop a write burst halfway. What may it do? Basic

    It may not end the burst early. It sends the remaining beats with all strobes LOW and WLAST on the last one. For reads it accepts the remaining beats and discards them.

    Spec§A3.1.2, p.44

    Give the beat addresses of WRAP, ARADDR 0x38, Size 8, Length 4. Intermediate

    Container 32 bytes; Wrap_Boundary = INT(0x38 / 32) × 32 = 0x20. Beats 0x38, then 0x40 = 0x20 + 32 wraps to 0x20, then 0x28, 0x30.

    SpecDerived from §A3.1.6, p.50

    On a 64-bit channel, AWADDR 0x1005, Size 4, Length 2, INCR. Which lanes do the two beats use? Intermediate

    Aligned_Addr 0x1004. Beat 1: Lower lane 5, Upper lane 0x1004 + 3 − 0x1000 = 7, so lanes 5–7 (3 bytes). Beat 2: Address 0x1008, lanes 0–3. 7 bytes in total.

    SpecDerived from §A3.1.6, p.50

    Is WSTRB = 0000 legal on a write beat? Is a strobe set outside the container legal? Intermediate

    All LOW is legal: inside the container any pattern is allowed, and that beat writes nothing. A strobe outside the container is never legal: those strobes must be LOW.

    Spec§A3.2.1.1, p.54

    Explain byte invariance with an example. Intermediate

    A byte at a given address always rides the same lane, whatever the endianness of the access. 0x0A0B0C0D stored big-endian at A puts 0x0A at A, on lane 0 of a 32-bit channel; stored little-endian it puts 0x0D at A, also on lane 0. Mixed-endian structures share memory without corrupting each other.

    Spec§A3.2.4, p.56–58

    What is a Regular transaction, and who benefits from the property? Intermediate

    Length 1, 2, 4, 8 or 16; full width if Length > 1; INCR or WRAP; INCR aligned to its container, WRAP aligned to Size. Subordinates that only accept these can drop narrow, unaligned and FIXED logic. A non-Regular-only Manager may not connect to a Regular-only Subordinate.

    Spec§A3.1.8, p.52

    A DMA must copy 6000 bytes from 0x0000_0F80 with 16-byte beats and Max_Transaction_Bytes 4096. Give the bursts. Advanced

    0x0F80 → 128 bytes to the 4 KB boundary: Length 8. Then 0x1000: 4096 bytes, Length 256. Then 0x2000: 6000 − 128 − 4096 = 1776 bytes, Length 111. Three bursts, all aligned to 16 bytes.

    SpecDerived from §A3.1, p.43 and §A3.1.3, p.45

    A downsizer receives a Non-modifiable INCR, Size 16, Length 4, and its output is 32 bits wide. Is it allowed to change the request? How? Advanced

    Yes. Non-modifiable normally fixes Size and Length, but the spec recognises that downsizing below Size must modify the transaction. It becomes Size 4, Length 16 with the same address and attributes. It may optionally signal that a modification happened through an IMPLEMENTATION DEFINED mechanism.

    Spec§A4.2.2, p.69

    What changed for burst length and FIXED between AXI3, AXI4 and Issue L? Advanced

    AXI3: all types 1–16 using AxLEN[3:0]. AXI4: INCR up to 256 with AxLEN[7:0]; WRAP and FIXED stay ≤ 16; long Non-modifiable INCR may be split for AXI3 compatibility. Issue L: same lengths; FIXED only with WriteNoSnoop/ReadNoSnoop; interfaces may disable FIXED (Issue K) and constrain WRAP to Modifiable cache lines (Issue L).

    SpecH.c §A3.4.1, p.A3-48–A3-49 · §A3.1.4, p.47–48 · Tables B4.2–B4.3, p.309–311

    Your Subordinate model computes the lanes for an unaligned FIXED burst by incrementing like INCR after beat 1. Is that right? Advanced

    No. FIXED never moves the address, so in the §A3.1.7 pseudocode the "aligned" flag never becomes TRUE. Every beat uses the first-beat formula: lanes from the start address up to the end of the aligned Size slot.

    Spec§A3.1.7, p.51 · §A3.1.4, p.47
