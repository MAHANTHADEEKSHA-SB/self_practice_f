AXI Qualifiers, Debug & User Field Guide

Around the core protocol sits a set of optional features that carry system information with a request or add special write types. This guide covers NSAID, PBHA, Subsystem ID and Arm Compression Technology, WriteZero and WriteDeferrable, MPAM, the Memory Tagging Extension, Trace, Loopback and User signals. It includes an MPAM field packer, waveforms, verification checks, interview questions and what changed since AXI4.

1 · Why these extras exist

Isolation

Who is asking, not just where

NSAID and Subsystem ID let firewalls tell Non-secure clients apart, beyond the address space.

Spec§A10.1, p.175 · §A10.3, p.178

Efficiency

Don't send what you don't need

WriteZero sends no data; ACT sends uncompressed data to a shared codec; WriteDeferrable lets accelerators refuse work instead of blocking.

Spec§A10.4, p.179 · Chapter A11, p.183–186

Platform features

Arm architecture extensions on the bus

MPAM (resource partitioning) and MTE (memory tagging) need the bus to carry their information end to end.

Spec§A12.1–A12.2, p.187–198

Debug and integration

Hooks that cost little

Trace follows a transaction, Loopback speeds up response lookup, User signals cover what nothing else does (but use them sparingly).

Spec§A12.3–A12.5, p.199–203

4 · Request qualifiers

NSAID

Protected Non-secure memory

  • 16 identifiers, each with its own permissions (none, RO, WO, RW) set by an MPU; mechanism IMPLEMENTATION DEFINED.
  • Only Non-secure PAS requests may use non-zero NSAIDs; 0 recommended when unprotected.
  • Caches must remember the NSAID a line was fetched with and use it for write-backs and snoop responses.
  • Snoop data with a different NSAID must go to memory and back through the permission check.
  • Invalidate-only snoops (MakeInvalid) must be replaced by clean-and-invalidate when memory protection is used.

Spec§A10.1, p.175–176

PBHA, Subsystem ID, ACT

More context per request

  • PBHA: 4 bits from a translation-table entry; meaning IMPLEMENTATION DEFINED; may become inaccurate through merging interconnects, caches or table changes, so integrators must check every hop.
  • Subsystem ID: 0–8 bits naming the originating subsystem: firewalls, snoop filters, profiling. Usage not defined by the spec.
  • ACT: WriteACT/ReadACT carry a 16–32-bit payload to an external compression codec. INCR, Device, System, ADDR[13:0] = 0, full-width when Length > 1, unique ID, DATA_WIDTH ≥ 128, untranslated. Size and Length must never change on the way.

Spec§A10.2–A10.4, p.177–181

5 · Other write transactions

WriteZero

Zero a line with no data

  • AW + B only; line sized and Regular.
  • AWSNOOP 0b0111, not exclusive, no tag op, unique ID.
  • Any Domain; Shareable behaves as WriteUniqueFull with zeros.
  • A Manager that issues it can't connect to a Subordinate without support.

Spec§A11.1, p.183

WriteDeferrable

A 64-byte store that may be refused

  • AWSNOOP 0b10000 (5-bit), BRESP 3-bit, System Domain, Device or Normal Non-cacheable.
  • 64 bytes as 1×64, 2×32, 4×16, 8×8 or 16×4; 64-byte aligned; all strobes; INCR.
  • 64-byte atomic: never split or merged; only to locations with 64-byte single-copy atomicity.
  • Responses: OKAY, SLVERR, DECERR, DEFER (try later), UNSUPPORTED; never EXOKAY. Maps to PCIe DMWr.

Spec§A11.2, p.184–186

6 · MPAM

Each request carries a partition ID (PARTID), a performance monitor group (PMG) and a security or address-space field. Memory-system components use them to partition and monitor caches and bandwidth per VM or application.

SpecTables A12.1–A12.6, p.187–188 · Derived encoding

Managers

Drive MPAM when AxVALID is HIGH; values IMPLEMENTATION DEFINED. A non-MPAM Manager in an MPAM system gets values added by the system, for example the PAS copied into the low bits.

Spec§A12.1.3, p.189

Interconnects

MPAM IDs are global; no need to make them unique. Propagate them or substitute IMPLEMENTATION DEFINED values.

Spec§A12.1.3, p.189

Subordinates

Sample MPAM with AxVALID and use it for partitioning (cache ways, bandwidth) and monitoring.

Spec§A12.1.3, p.189

7 · Memory Tagging Extension

Every 16 bytes of memory has a 4-bit Allocation Tag. Pointers carry a Physical Tag. MTE on AXI moves tags with data, updates them, and checks them.

Spec: Table A12.10, p.193 · Table A12.12, p.194
TagOpRead (ARTAGOP)Write (AWTAGOP)
00Invalid: no tags, RTAG zeroInvalid: no tag work
01Transfer: a tag with every beat, every granule touchedTransfer: tags are Clean, may be cached
10ReservedUpdate: tags Dirty, write those flagged in WTAGUPDATE
11Fetch: tags only, data not valid; line sized and RegularMatch: compare with stored tags; data written even if it fails; two-part response

Rules when tags travel

  • ≤ a cache line, no line crossing; physical address (AxMMUVALID LOW); INCR or WRAP.
  • Normal Write-Back: AxCACHE[1:0] = 11, [3:2] ≠ 00.
  • Unique in-flight ID for reads with Transfer/Fetch and writes with Transfer/Update/Match.
  • Tags cached coherently like data (Invalid, Clean, Dirty); tags valid only when data is; dirty tags written back even on MakeInvalid/ROMI.
  • Support levels: Standard (all), Simplified (no Match, no partial tag writes), Basic (limited ops). Not with DATA_WIDTH ≤ 32.
  • Non-tagging memory: data handled normally, tags dropped, RTAG zero, one combined Match response.
  • Atomics may use Match only; their RTAG is not valid.

Spec§A12.2.1–A12.2.8, p.190–197

8 · Trace, Loopback and User

Trace

One bit per channel. Recommended: echo the request's trace bit on every response transfer (and a clear bit for untraced requests), preserve it through pass-through components, propagate WTRACE; for Atomics, RTRACE follows AWTRACE. Use is coordinated system-wide.

Spec§A12.3, p.199 · Table B4.3, p.312

Loopback

0–8 bits per direction. BLOOP = AWLOOP (on the Completion if BCOMP exists), RLOOP = ARLOOP on every beat, and RLOOP = AWLOOP for Atomics. Not unique; intermediates may swap in their own values and restore them.

Spec§A12.4, p.200–201

User

Recommended to avoid. Request 0–128, data 0–512, response 0–16 bits (guidance). RUSER = data part + response part. Recommended: data width a multiple of the byte lanes, response bits constant per transaction, response info in low RUSER bits.

Spec§A12.5, p.202–203

9 · Why each rule exists, with real-time examples

Qualifiers§A10.1.2 p.176

A cached line remembers its NSAID

Write-backs and snoop responses must use the NSAID the line was fetched with.

Why

Otherwise a client could read protected data under one NSAID and have it written back, or forwarded to another client, under a different one, bypassing the MPU.

Real-time example

A DRM video decoder (NSAID 5) reads a protected frame; the line is later evicted. The write-back must carry NSAID 5 so the MPU checks it against the protected region's rules.

If you break it

Protected content leaks through the cache.

Sources
  • Spec§A10.1.2, p.176
  • IllustrativeDRM example
Qualifiers§A10.4.3 p.181

ACT requests never change shape

An ACT transaction must never have its Size or Length changed, even where Non-modifiable transactions normally may be.

Why

The ACT payload describes exactly this transaction's Size and Length for the codec. Splitting or narrowing it would leave the codec with a payload that no longer matches the data.

Real-time example

A 256-byte ReadACT on a 128-bit path to the codec: every link must be at least 128 bits wide and accept the burst unsplit.

If you break it

Corrupted decompression; the topology must be planned for ACT.

Sources
  • Spec§A10.4.3, p.181
  • Illustrativesizes
Other writes§A11.2.2 p.185

WriteDeferrable is 64-byte atomic

Never split or merged; only to locations with 64-byte single-copy atomicity.

Why

The accelerator accepts or refuses the whole descriptor. Half a descriptor accepted and half deferred would corrupt its queue.

Real-time example

A crypto accelerator's submission portal behind a CXL/PCIe link takes one 64-byte work descriptor per write; DEFER means the queue was full, so software retries.

If you break it

Torn descriptors, which an accelerator might execute.

Sources
  • Spec§A11.2, p.184–185
  • Illustrativeaccelerator
Other writes§A11.1 p.183

WriteZero needs a supporting Subordinate

A Manager that issues WriteZero can't be connected to a Subordinate that doesn't support it.

Why

There is no data to fall back on. A Subordinate that ignored AWSNOOP would see a write with no W beats and wait forever, or write garbage.

Real-time example

An interconnect in front of a legacy SRAM converts WriteZero into a normal write with 4 W beats of zeros.

If you break it

A hung W channel at the legacy Subordinate.

Sources
  • Spec§A11.1, p.183
  • Backgroundconversion
MTE & MPAM§A12.2.6 p.194–196

Match writes the data anyway

With AWTAGOP Match, memory is updated even when the tags don't match; the result is reported separately.

Why

Stores are posted; the CPU has already retired the instruction. MTE reports violations (synchronously or asynchronously at the CPU) rather than blocking the store, keeping the write path simple and fast.

Real-time example

A use-after-free store in Android with MTE in async mode: memory is overwritten, the Match response says Fail, the kernel later reports the fault.

If you break it

A Subordinate that drops data on Fail behaves differently from what software expects.

Sources
  • SpecTable A12.12, p.194
  • BackgroundMTE modes
MTE & MPAM§A12.2.3 p.191–192

Dirty tags must never be lost

Dirty tags are written back or passed dirty when evicted, even by MakeInvalid or ReadOnceMakeInvalid.

Why

Discarding data is sometimes acceptable (MakeInvalid), but tags define memory safety for the whole allocation. Losing them would silently disable checking.

Real-time example

A MakeInvalid hits a line whose data is disposable but whose tags were just updated by malloc; the tags still go to memory.

If you break it

False tag-check failures or missed violations later.

Sources
  • Spec§A12.2.3, p.191–192
  • Illustrativemalloc
Debug & user§A12.5 p.202

Avoid User signals

User signals are allowed but recommended against; the protocol defines no meaning for them.

Why

Two IPs using the same USER bits for different things can't be connected without glue, and interconnects must decide what to do with USER on splits, merges and width changes.

Real-time example

One vendor's DMA uses AWUSER[3:0] for a stream ID; another's system cache uses AWUSER[3:0] as an allocation hint. Connected, the DMA's stream IDs become random cache policies.

If you break it

Silent misbehaviour after integration. Prefer defined features (MPAM, Subsystem ID, Loopback) where they fit.

Sources
  • Spec§A12.5, p.202–203

13 · Verification

Assertions

  • NSAID ≠ 0 only with Non-secure PAS. §A10.1.1, p.175
  • ACT: AxSNOOP 0, INCR, Device, System, ADDR[13:0] = 0, unique ID; never resized by interconnects. §A10.4, p.180–181
  • WriteZero: no W beats; line sized; unique ID. WriteDeferrable: 64 B legal shapes, aligned, all strobes, System. §A11, p.183–185
  • MTE: tag ops only on legal Opcodes (Tables A12.11, A12.13); tagged transactions physically addressed, Normal WB, no line crossing; WTAGUPDATE only for Update; BTAGMATCH response pairs per Table A12.15. §A12.2, p.192–197
  • Loopback: BLOOP/RLOOP equal to the request's value. §A12.4, p.201

Scenarios and coverage

  • WriteDeferrable: OKAY, DEFER, UNSUPPORTED, SLVERR; retry loops.
  • MTE Match: Completion first, Match first, combined; Pass and Fail; Atomic with Match; Subordinate without MTE.
  • MPAM: every support/RME combination, max PARTID, propagation through each hop.
  • Trace/Loop through interconnect splits and width converters.
  • Coverage: TagOp × Opcode × MTE_Support; NSAID values × PAS; WriteDeferrable shape × response.

14 · Test yourself

What does WriteZero save, and what does it need from the Subordinate? Basic

All W beats of a line of zeros: only AW and B. The Subordinate must support it; a Manager that issues WriteZero can't connect to one that doesn't.

Spec§A11.1, p.183

What responses can a WriteDeferrable get, and what does DEFER mean? Basic

OKAY, SLVERR, DECERR, DEFER, UNSUPPORTED (never EXOKAY). DEFER: not performed now, might succeed if retried.

SpecTable A11.3, p.185

Why are User signals discouraged? Basic

The protocol defines no meaning for them, so two components may use them incompatibly, and converters can't know how to transform them.

Spec§A12.5, p.202

MPAM_12_1 with RME: how wide is AxMPAM and where is PARTID? Intermediate

15 bits: MPAM_SP [1:0], PARTID [13:2], PMG [14].

SpecTable A12.6, p.188

What are the two responses of an MTE Match write, and can they be combined? Intermediate

Completion (BCOMP HIGH, BTAGMATCH 01) with normal ordering, and Match (BCOMP LOW, BTAGMATCH 10 Fail or 11 Pass) with no ordering. Yes: one transfer with BCOMP HIGH and BTAGMATCH Pass or Fail.

Spec§A12.2.6, p.196–197

What must a cache do with NSAID on write-back and snoop? Intermediate

Use the NSAID the line was fetched with. If a snoop returns data with a different NSAID than the read, write it to memory with the snoop's NSAID and re-read with the request's NSAID, passing through the permission check.

Spec§A10.1.2, p.176

Why must an ACT transaction's Size and Length never change? Advanced

The ACT payload is specific to that Size and Length; the external codec relies on it. That's stricter than ordinary Non-modifiable transactions, which may be split if Length > 16 or narrowed by downsizing.

Spec§A10.4.3, p.181

Which TagOps can an Atomic transaction use, and are its RTAGs valid? Advanced

Only Match. Read data from an Atomic has no valid RTAG (recommended zero). A 32-byte AtomicCompare with Match uses the same tag for compare and swap halves.

Spec§A12.2.8, p.197

What happens when an MTE Match write reaches memory without tag support? Advanced

The data is written normally and a single combined response is given (BCOMP HIGH, BTAGMATCH 10 is listed as "Match Fail or MTE Match not supported"); OKAY unless the equivalent non-MTE write would have failed.
