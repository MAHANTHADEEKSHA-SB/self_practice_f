Spec notes found while building the guides

Places where the spec is easy to misread, where Issue L quietly differs from H.c, or where a later issue corrected an earlier one. Each is explained in the linked guide.

Dropped explanation

Why BVALID waits for AW is no longer in the text

H.c explained that a write response hands hazard-checking responsibility to the Subordinate, and warned about the AW/W deadlock. Issue L keeps both rules but drops the explanations.

SpecH.c p.A3-46 vs §A2.3.2.1, p.31 · Channels guide

Easy to misread

"May wait for VALID" is not "may be combinational on VALID"

A receiver may wait for VALID before READY, but §A2.1.1 forbids combinational input-to-output paths on an interface. A READY that waits for VALID can rise one cycle later at the earliest.

Derived §A2.1.1, p.27 with §A2.3, p.29 · Channels guide

Correction in Issue L

The WRAP address formula was wrong before

Issue L corrects the expression for the address of each transfer in a wrapping burst to Address_N = Aligned_Addr + ((N − 1) × Size) − (Size × Length).

SpecTable B4.3, p.311 · Bursts guide

Correction in Issue K

Read_Interleaving_Disabled on AXI5-Lite

Issue J constrained it to True for AXI5-Lite; Issue K says that was wrong and it should be False.

SpecTable B4.2, p.310 · Signals guide

Wording fixed in Issue J

"AxLEN is 1, 2, 4, 8 or 16" in H.c's Regular definition

H.c defined a Regular transaction with "AxLEN is 1, 2, 4, 8, or 16", but AxLEN is Length − 1. Issue L says "Length is 1, 2, 4, 8, or 16", which is what was meant.

SpecH.c §A3.4.3, p.A3-53 vs §A3.1.8, p.52 · Bursts guide

Easy to misread

An unaligned FIXED burst never becomes aligned

In the §A3.1.7 pseudocode only a moving address sets the "aligned" flag. FIXED never moves, so every beat uses the first-beat lane formula. Models that copy INCR behaviour after beat 1 get the lanes wrong.

Derived §A3.1.7, p.51 · Bursts guide

Moved, not removed

AxLOCK left the Non-modifiable table

H.c's list of fields a Non-modifiable transaction must keep included the lock type. Issue L's Table A4.3 lists address, size, length, burst and protection only; AxLOCK appears instead under "must not be changed" for Modifiable transactions. Since Non-modifiable is stricter, treat AxLOCK as fixed in both.

Derived H.c Table A4-2, p.A4-64 vs Table A4.3, p.69 and §A4.2.2, p.70 · Attributes guide

Easy to misread

One ARCACHE value, two memory types

ARCACHE 0b1010 is both Write-Through No-Allocate and Write-Through Write-Allocate (likewise 0b1110, 0b1011, 0b1111). On a read, the write-allocate hint has nothing to act on, so the table gives both types the same read encoding.

Derived Table A4.4, p.71 · Attributes guide

Quiet change

Device vs Normal ordering became a property

H.c said its same-location guarantees "imply" ordering between Device and Normal accesses. Issue L adds "with the same cacheability", removes any ordering between Cacheable and Device/Non-cacheable requests, and makes Device vs Normal Non-cacheable ordering depend on Device_Normal_Independence (default False, ordered).

SpecH.c §A6.5.1, p.A6-88 vs §A5.3.4 and §A5.3.8, p.94–97 · Ordering guide

Inconsistency

Missing AxDOMAIN: Non-shareable or Shareable?

§A8.3.4 first says that without Domain signals, Cacheable requests are assumed Non-shareable; a few lines later, after Table A8.5, it says Cacheable requests are assumed Shareable. CMOs without AxDOMAIN are assumed Non-shareable (§A9.3). Fix the assumption in your integration spec.

Derived §A8.3.4, p.135 · §A9.3, p.156 · Caches guide

Typo in the spec

UnstashTranslation text says "StashTranslation"

In §A13.10, the bullet for a physical address reads "the StashTranslation request has a physical address and the MMU should deallocate the relevant Granule Protection Table entry". The section is about UnstashTranslation, and deallocation only makes sense for it; read it that way.

Spec§A13.10, p.220 vs §A13.9, p.219 · Untranslated & DVM guide

Easy to misread

AxMMUVALID defaults to 1, not 0

An interface without AxMMUVALID is treated as always untranslated. Issue L corrected the default from 0b0 to 0b1, and added the rule that translated and untranslated requests must not share in-flight IDs, which was intended from the start but missing.

SpecTable A13.2, p.207 · §A13.7, p.217 · Table B4.3, p.311 · Untranslated & DVM guide
